### 1.2 问题清单

| # | 问题 | 性质 |
|---|---|---|
| P1 | **sherpa 引擎卡 `ok: true` 写死**——melo 模型未下载也显示"就绪"，点启用后出片才失败 | 缺陷 |

| P6 | **ASR「当前生效」联动弱**：识别参数区选了 medium，但该模型是否已安装、下载到什么进度，参数区不显示，要去模型库找 | 结构 |

| P10 | TTS 引擎的差异维度没有讲全：GPU 加速支持与否、语言/方言覆盖、克隆能力、使用限制（如云端接口的频率限制）——用户只能靠名字和一句描述猜 | 文案 |

## 二、目标信息架构

### 2.1 统一骨架：每域两段式「当前生效 → 资产库」

三个域的心智模型统一为一句话：**上面是"现在用的是谁"（可改可试），下面是"有哪些可选"（可装可删）**。

```
┌─ 当前生效（大卡）────────────────────────────┐
│ 引擎/模型名 · 状态徽标 · 关键参数行 · 主行动按钮 │
└──────────────────────────────────────────┘
┌─ 资产库 ────────────────────────────────────┐
│ 搜索/筛选 工具行                              │
│ 分区列表（可用 / 储备）                        │
│ 行 = 状态点+名称+评级+体积+可行性+动作          │
└──────────────────────────────────────────┘
```

### 2.2 逐 Tab 目标布局

**总览（驾驶舱）**

```
本机运行条件（显卡/内存/磁盘 + 整机结论）      ← 从页尾提到页首：先定调"这台机器能吃什么"
三张能力卡（合并路线卡职责）：
  每卡 = 图标+域名+当前引擎/模型+状态点
       + 一条主行动按钮（按状态变化）：
         未就绪 → 「去下载/去配置」（替代原路线卡的入口职责）
         已就绪 → 「去调整」（跳对应 tab 微调）
```

**语音识别 ASR**

**语音识别 ASR**

```
当前生效卡：默认模型（Select）+ 运行设备 + 识别语言
           卡内右侧内联显示该模型的安装态与下载进度（解决 P6）
           设备=自动 且 GPU 可用时显示「转写将走 GPU」结论行
GPU 加速卡：保留（CUDA 运行库下载语境），标题改「转写加速」明确分工（P7）
模型库：推荐卡/搜索/档位分组不变；工具行加「手动导入」（P9）：
        选择本地模型文件夹 → 布局完整性校验（blobs/refs/snapshots 三件套、
        关键文件存在性）→ 缺元数据时「一键修复」→ 成功入列
        工具行另加「放置路径说明」：一键复制目标路径 + 命名规则提示
```

**配音 TTS**

```
当前生效卡：引擎三选（分段控件 Segmented，替代三张平铺卡，节省高度）
           + 音色下拉（带搜索）+ 「试听」按钮（合成一句固定台词，P8）
           + 该引擎模型安装态内联（Kokoro/sherpa 缺模型时就地给下载按钮，解决 P5）
           + 引擎差异标注行：GPU 加速支持 · 语言/方言覆盖 · 使用限制（P10，
             如云端引擎注明「免费但高频使用可能限流，出片场景天然低频」）
引擎与模型库（按使用门槛分区，P2/P10）：
  ├─ 即开即用 · 云端免费（Edge）——无需下载，标注限流提示
  ├─ 本地离线（Kokoro / melo）——免费离线数据不出机，标注 GPU 支持与语言覆盖
  └─ 储备 · 引擎未接入（IndexTTS2 / VibeVoice）——独立折叠分区，默认收起；
     行内注明体积与「接入排期 P-2」，下载按钮置灰并说明原因
```

**文案 LLM**

```
当前生效卡：启用中的端点（名称/模型/base_url）+ 测试连接 + 编辑
配置列表：多实例管理（不变）
```

### 2.3 硬件信息分工定调（P7）

- **总览 MachinePanel** = "这台机器有什么、能吃什么"（选模型的依据）
- **ASR 转写加速卡** = "转写这个环节能不能吃 GPU"（CUDA 运行库下载入口只在此处）
