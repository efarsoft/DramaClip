# service/02 · 引擎层设计（engines/）

> 引擎 = 纯业务逻辑：输入/输出皆为可序列化数据结构，不感知 transport，不裸写 SQL（经 infra repos），进度经注入的 `ProgressReporter`。
> 数值参数依据全局 `06-经验参数表.md`；功能语义依据 `01-技术方案-原案.md` 对应章节（下文标注）。

> ⚠️ **实现状态（2026-09-10 核对 HEAD）**：本文登记的 `analysis/face_detector.py`、`analysis/quality.py`、`semantic/plot.py` **三个模块在 v2 代码中不存在**，属设计意图而非现状。因此 **v2 当前没有任何画面理解能力**——分析层只有 ASR 转写、场景切换密度、音频能量，语义层全部吃文本。本文后续涉及视觉特征、画质、剧情结构化的条目一律按"未实现"理解。画面通道立项见 `docs/superpowers/specs/2026-09-10-dramaclip-ui-redesign-design.md` §10。

## 通用约定

- 每模块配 Pydantic 输入/输出模型（定义在模块内 `models.py`）；
- FFmpeg 一律经 `infra.ffmpeg`（runner/filters），禁止裸 subprocess；
- 模型加载懒加载 + 单例句柄（显存受 `hardware.max_parallel_jobs` 约束）。

## 1. analysis —— 第一层：两阶段分析（原案第三章 + 第三章附）

| 模块 | 职责 | 要点 |
|------|------|------|
| `prescreen.py` | 阶段一轻量预筛（每集 1-3s，纯 FFmpeg） | 采集：音频能量峰值密度（`astats`）、场景切换密度（`select=scene`）、人声活跃度（`silencedetect`）、运动幅度（`signalstats` 帧差）；加权分 0-100，公式按原案 3附.4；**在服务进程内由 api 调度，无需 GPU/模型** |
| `pipeline.py` | 阶段二编排 | 集数 ≤ `analysis.full_threshold`(15) → 全量；否则预筛排序取推荐集；逐集跑 transcriber→scene→audio→(semantic) 并落库；支持断点续跑（已 done 的集跳过） |
| `transcriber.py` | ASR 双引擎 | 接口 `transcribe(audio_path, engine, model) → AsrResult{segments[{start,end,text,speaker?,emotion?}]}`；SenseVoice（本地，含 VAD+情绪标签）/ faster-whisper（large-v3，词级对齐）；模型路径经 model_manager 解析 |
| `scene_detector.py` | 场景切割 | PySceneDetect，阈值 30，场景规整 2-8s（经验参数表 §3） |
| `audio_analyzer.py` | 音频分析 | librosa：能量曲线、BPM、静音比；静音段供 dedup 降级使用 |
| `face_detector.py` | 人脸+表情（P1） | 检测+跨帧跟踪；用于说话人视觉特征与竖屏裁切参考 |
| `quality.py` | 画面质量 | 清晰度（拉普拉斯方差）、过曝/欠曝、运动模糊 |

## 2. semantic —— 第二层：LLM 语义（原案第四章）

| 模块 | 职责 | 要点 |
|------|------|------|
| `llm_client.py` | OpenAI 兼容抽象 | 端点三元组来自 settings（ADR-005，可切本地 Ollama）；`chat_json(prompt, schema)` 强约束 JSON 输出 + 校验重试（≤2 次）；**降级**：连续失败/未配置 → 抛 LlmUnavailable，调用方走关键词降级（W3 DoD） |
| `plot.py` | 剧情结构化 | 输入全剧 ASR 摘要 → 输出 `{characters, scenes, summary}` |
| `conflict.py` | 冲突打分 | 每场景/片段 0-100 分 + 理由；输入 ASR 情绪 + 台词 + 场景数据 |
| `ranker.py` | 高光综合排序 | `冲突分 + 音频能量 + 画质 + 情绪` 加权（原案 4.3），第一层信号权重参考经验参数表 §2 |
| `genre.py` | 题材分类 | 复仇/甜宠/悬疑/逆袭/家庭伦理…，用于策略与字幕预设推荐 |

## 3. narration —— 九模式编排（原案第六章）

**plan_data 统一结构**（存 `narration_plans.plan_data`）：

```json
{
  "mode": "intro_narration",
  "timeline": [ { "source_episode", "start", "end", "audio": "original|narration|ducked",
                  "subtitle": {...}, "transition": "cut|fade|black|flash" } ],
  "narration_texts": [ { "id", "text", "voice", "tts_ref?" } ],
  "strategy": { "platform", "target_duration_range", "aspect" }
}
```

| 模块 | 职责 | 要点 |
|------|------|------|
| `orchestrator.py` | 总编排 | `generate_plan(mode, analysis, strategy) → plan_data`；**一键全部生成**：LLM 一次产出全部模式文案 → TTS 串行（GPU 约束）与无 TTS 模式（剧情/纯原片/金句流）编码并行（原案 6.12） |
| `modes/*.py` | 九模式编排器（一模式一文件） | `intro`（片头解说：30-60s 引子+正片）/ `raw_clip`（纯原片：冲突分筛选+时间线编排，**零加工**：不加字幕不遮罩）/ `cross` / `full` / `dialogue` / `subtitle_flow` / `ultra_short` / `dual_host`(P2) / `monologue`(P2)；P0 落地 intro + raw_clip |
| `scriptwriter.py` | LLM 文案生成 | 各模式 prompt 模板常量；输出带时间轴的分段文案 |
| `dialogue_selector.py` | 剧情解说对白筛选 | 两遍：台词质量打分（信息密度/情绪/独立性/金句潜力）→ LLM 起承转合重排（原案 6.6） |
| `hook_generator.py` | 超短悬念钩子文案 | 一句钩子 + 一句收尾 CTA（原案 6.9） |
| `quote_extractor.py` | 金句提取 | 高冲突/高情绪台词 → 字幕金句流的字幕序列 |

## 4. subtitle —— 共享字幕引擎（原案第六章附A/B）

| 模块 | 职责 | 要点 |
|------|------|------|
| `ass_generator.py` | ASS 生成 | 四维度参数 → ASS 标签：逐字/逐词节奏=多行时间偏移；弹入/缩放/震动=`\t()` 关键帧；布局=Alignment+`\N`；情绪色=`\c&H`+描边（映射表按原案 6A.2-6A.5） |
| `presets.py` | 预设加载合并 | 内置 `resources/subtitle-presets/*.json` + DB 用户预设，解析顺序 用户>内置>默认（ADR-008）；`list_presets()` 返回合并视图 |
| `emotion_matcher.py` | 情绪→样式匹配 | LLM 情绪标签 + intensity → 动态覆盖预设参数（原案 6A.7 规则表） |
| `mask.py` | 原片字幕遮罩 | 固定参数 y=0.88/h=0.12/opacity=0.6；**纯原片模式禁用**（原案 6B） |

## 5. dedup —— 智能消重（原案第八章，参数=经验参数表 §1）

| 模块 | 职责 |
|------|------|
| `jitter.py` | 安全切点：SRT 台词保护区（行首-0.2s~行尾+0.15s）→ 命中即 snap 外避让；静音间隙内 ±0.08~0.3s 随机抖动；无 SRT 降级能量检测（80ms RMS，阈值 max(均值×1.65,120)）；抖动后 <0.45s 回退 |
| `params.py` | 每片段独立随机生成：微变速 0.996~1.004（atempo 变速不变调）、微缩放 0.982~0.988、eq 对比度/亮度抖动；输出 filters 构建所需的参数对象 |

元数据擦除（`-map_metadata -1`）在 exporter 命令组装层强制注入。

## 6. tts —— 配音（原案 1.2）

```python
class TtsEngine:                       # base.py
    def synthesize(text, voice, opts) -> TtsAudio{path, duration}
```

| 模块 | 要点 |
|------|------|
| `engines/edge.py` | Edge TTS（免费可用，W5 首个落地） |
| `engines/kokoro.py` | Kokoro 本地（默认音色 zf_001，经验参数表 §5） |
| `engines/indextts.py` | IndexTTS-2 情感/克隆（P2） |
| `factory.py` | 按 settings `tts.engine` 实例化；**缓存优先**：text+engine+voice+参数 哈希查 `tts_cache` 表，未命中才合成并落缓存 |
| `subtitle/tts 试听` | `tts.preview` 经 factory 直调 |

## 7. strategy —— 推广策略适配（原案第五章）

`presets.py` 内置平台参数表：快手信息流（15-60s / 9:16 / 强冲突开头）、星图长视频（60-300s）、抖音推广（15-90s / 悬念钩子）、视频号（30-120s / 情感向）。输出 `StrategySpec{platform, duration_range, aspect, style_hint}` 供 narration 编排与文案风格约束。

## 8. exporter —— 编码导出（原案第七章）

| 模块 | 职责 | 要点 |
|------|------|------|
| `encoder.py` | 滤镜链编排 | 顺序固定：**解码 → 遮罩(mask) → 消重(微缩放/eq) → ASS 字幕烧录 → 转场 → 编码**；`-map_metadata -1` 全程；硬编码 NVENC 探测可用即用；进度解析 `-progress` |
| `mixer.py` | 混音 | 音量层级：解说 1.0 / 原声（overlay 段 ducked 0.15~0.2 / 原片段 1.0）/ BGM 0.1~0.3；输出 plan_data.timeline 的音频装配参数 |

转场：硬切（默认）/ 叠化 xfade / 黑场 / 闪白，按 plan_data.timeline[].transition。
