# 08 · 转写精炼层设计：LLM 断句 + 语境校对（单次调用 + 对齐审计护栏）

> 状态：已实现（本文为设计意图与实测依据的存档）。前置阅读：07-ASR-OCR融合质量报告.md。

## 0. 背景与根因

三代分行的问题链：v0 逐窗对齐刀劈词（「大明两」）→ v1/v2 驻留窗分行（碎行「名在外的锦」）→ v3 收口（佐证计数）。根因不变：**语音时间轴与字幕时间轴是两套时钟**（ASR 字级戳是插值，与字幕窗中位差 1.98s、最大 7.75s 且方向翻转），用字幕窗切语音字流，切点必然错位；声学 VAD（fsmn-vad）又被 BGM 填满停顿——「人声停了音乐没停」，声学断句分不清停顿与乐段。

新前提：管线里已有 LLM（DeepSeek）。**语义断句不受 BGM 影响**——「大明两大蛀虫」是一个短语、「干的第一件事」是新句开头，这是语言判断而非声学判断。

## 1. 目标与非目标

**目标**：G1 断句符合语义（修并句/碎行/串音三病）；G2 同音错字被语境修正（传承→穿成、诸传→蛀虫、东昌→东厂）；G3 句时间=首末字戳（句级跨度准）；G4 LLM 无法丢内容或改写句式（对齐护栏，数学可验）；G5 分档——LLM 不可用/护栏拒绝 → 回退 paraformer 原生分段，不挡分析。

**非目标**：不碰字幕擦除的 OCR 通道；不做说话人分离；不追求字级时间戳精度；VAD 辅助断句工作流移除（业主裁决：语义断句取代声学断句；funasr 引擎内部 fsmn-vad 保留不动）。

## 2. 架构位置

```
本地 ASR（paraformer 字流+字戳；引擎内部 fsmn-vad 原样保留）
→ 【llm_refine：单次 LLM 调用——断句+校对合并】（本设计）
→ 【对齐审计护栏（纯代码）】
→ OCR 交叉验证（补字+分歧标记；fusion 角色收缩为证据源）
→ 语义分析 → 金句/文案下游
```

## 3. 单次调用设计

**输入**：① 原始字流（concat(words.text) 纯内容字+每字时间戳）② 字幕读数（OCR 条文本，标注"画面叠加字幕，仅供纠错参考"）③ 语境（剧名、挖掘热词）。LLM 用现有 LlmClient（DeepSeek），temperature 0.3。

**提示词要点**：断句到短剧字幕粒度；修同音/近音错字（举例「传承崇祯」→「穿成崇祯」、「东昌提督」→「东厂提督」）；输出 JSON `{"sentences": [...]}`；拼接逐字一致（同音替换除外）；禁止增删/改写/总结；可加标点；字幕读数里转写字流没有的内容不得搬入。

## 4. 对齐审计护栏（纯代码，四判据）

`merged = concat(sentences)` 与原始字流做 SequenceMatcher 对齐：

| 判据 | 规则 |
|---|---|
| R1 内容删除 | 原文有而输出无的**非标点字** → 拒绝整份输出（丢话最危险） |
| R2 替换/插入拼音 | 错配字对必须拼音同音或近音（pypinyin 无声调相等=同音；同声母或同韵母=近音）→ 否则拒绝 |
| R3 插入有据 | 输出多出的连续字串必须出现在字幕读数中（OCR 有据补字）；LLM 凭空造的字拒绝 |
| R4 标点豁免 | LLM 添加的标点自由（可读性，无内容风险） |

**通过** → 按对齐映射句时间戳（句首/末个"有 raw 对应"的字戳）；**拒绝** → 回退原生分段 + WARN + `needs_review` 语义。

## 5. 失败语义（分档）

| 失败 | 行为 |
|---|---|
| LLM 未配置/不可用/超时 | 回退原生分段，WARN，不挡 |
| JSON 解析失败 | 格式强化重试 1 次 → 仍失败回退 |
| 护栏 R1/R2/R3 拒绝 | 回退原生分段（完整句兜底），人工抽查入口 |

任何路径不挡分析；下游语义永远拿到有效段。

## 6. 数据模型与可观测

- `AsrSegment.source` 增 `"llm_refined"` 值（可选串，无破坏性）；转写卡徽标「AI 校对」
- 审计走现有 `llm_traces` 留痕体系
- 护栏拒绝时 WARN 带判据与差字数

## 7. 成本

每集 1 次调用（输入 ~1-2K tokens + 输出 ~1K）：DeepSeek 数秒、不到一分钱。护栏纯 CPU 毫秒级（difflib 对齐）。重试封顶 1 次。

## 8. 测试与验收

单测（桩 LLM）：护栏 R1/R2/R3 各分支（同音过/近音+OCR 证据过/无关拒/无据插入拒）、时间戳映射（含插入字）、回退链（未配置/调用失败/护栏拒绝）、重试强化。
e2e：第一集真跑（真转写+真 LLM），验收「皇帝干」串音消失、诸传→蛀虫被修、段数与字幕条数量级匹配、trace 留痕。

## 9. 风险与对冲

| 风险 | 对冲 |
|---|---|
| LLM 输出格式抖动 | 重试 1 次 + 回退兜底 |
| 近音替换误改（把对的改错） | 首版近音档要求字幕读数有据；同音档无风险；修改对照可在转写卡人工纠 |
| 超长集字流 | 68s 集 ~500 字，余量 10 倍；超长按句号分批（首版不做） |
| trace 体积 | 现有 llm_traces 轮转机制 |

## 10. VAD 辅助断句工作流：移除

业主裁决：语义断句取代声学断句。区分两个东西——本工作流移除；funasr 引擎内部 fsmn-vad 保留不动（ASR 引擎自有组件）。若未来 LLM 断句实测不稳，声学 VAD 参数调优（max_end_silence_time / speech_noise_thres）作为兜底再评估。
