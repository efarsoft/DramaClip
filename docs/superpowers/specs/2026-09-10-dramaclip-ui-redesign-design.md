**日期**：2026-09-10 · **状态**：待用户审阅 · **并行工作线**：与 `docs/05-开发路线图.md` 的 P3 批次表**互不合并**（那份由用户自维护）

## 1. 定位与主循环

产品是**短剧 CPS 切片分销的量产工具**，不是视频编辑器。界面必须按操盘手的真实循环排布，而不是按技术分层排布：

```
新增项目 → 转写分析 → 整剧规划 → 出片渲染 → 质检挑片
（素材已在本地）        ↑                                    │
                        └──────（发布在各平台后台人工完成）←──┘
```

**产品边界（用户纠正）**：软件从**素材已经落地本地**之后才开始。上游片单（`任务名称 · 短剧/真人剧 · 付费/免费 · 剧场 · 素材链接`）与网盘下载都在产品之外，不做导入、不做下载管理。展示片单形态的意义只有两点：① **不存在"授权书"这个东西**，故本规格移除授权留痕设计；② **下载后通常按「任务名称」建文件夹**，所以新增项目时剧名直接取文件夹名即与片单天然对齐，无需导入器、无需任何额外录入。片单里的类型/付费性/剧场三列**不进产品**（用户判定：增加操作负担、无对应收益）。

**核心处理单元 = 整部剧**，不是单集。一次提交（剧 × 模式）→ 每模式产出 1..K 条**卖点角度互异**的跨集方案 → 队列并行渲染 → 成品库按剧分组质检。

界面必须服务的三条判断：
1. **哪部剧卡在哪一步**（10 部剧并行是常态）；
2. **这批片能不能发**（质检是每日真瓶颈，成材率约 15%）；
3. **模型到底看到了什么**（任何降级、截断、覆盖度缺失都必须可见，不能静默）。

第 3 条是本次重规划的新增主张：今天 LLM 超时降级、跨集输入截断、字幕预设失效、失败集与未分析集同形，四类静默问题在界面上全部不可见。

## 2. 信息架构

### 2.1 导轨：8 项，分两组（上组按循环排，下组钉底）

**上组 · 生产循环**

| 序 | 名称 | 路径 | 职责 | 相对现状 |
|---|---|---|---|---|
| 1 | 工作台 | `/` | 今日待办 + 队列摘要 + 最近成品 + 新增项目入口 | 改造（从介绍页变开工页） |
| 2 | 剧库 | `/dramas` | 全部剧的进度环与阶段定位；批量新增项目 | 原 `/projects` 改造 |
| 3 | 队列 | `/queue` | 跨剧全局任务：组级进度、降级留痕、取消/重试 | **新增** |
| 4 | 成品 | `/works` | 按剧分组 + 逐片钩帧封面 + 自检结论 + 挑选与批量动作 | 大改 |
| 5 | 工具箱 | `/tools` | 单发小工具：转写取稿 / 文案转字幕 / 配音合成 / 抽帧取图 / 媒体体检 / 对标拆解 / 图片生成（文生图 + 图生图） | **新增**（§4.7） |

**下组 · 配置与元信息**（一条 `border/subtle` 分隔线隔开，视觉上沉底）

| 序 | 名称 | 路径 | 职责 | 相对现状 |
|---|---|---|---|---|
| 6 | 引擎 | `/engines` | ASR/TTS/LLM/视觉/图像 五能力、模型库、连通自检 | 由 `/models` 更名，与页内「引擎中心」统一 |
| 7 | 设置 | `/settings` | 生产线默认值（含 K）/ 分析 / 字幕 / 输出 / 存储 / 代理 | 改分区 |
| 8 | 关于 | `/about` | 项目信息 · 版本 · 本地数据入口 · 开源许可 · 公众号与打赏码 · 授权声明 | **新增**（§4.8，渲染为覆盖层） |

**分组规则**：上组五项就是生产循环本身（开工→投料→跑→挑→杂活），下组三项都不产生内容。一条分隔线把两种性质切开——这样"按循环排序"才成立，否则工具箱（侧门）与引擎（配置）夹在循环中间，规则是破的。桌面软件惯例也是把设置/关于钉底。

**高亮规则（修既有缺陷）**：进入剧空间 `/drama/:id` 时，导轨「剧库」保持高亮，且 PageHeader 显示当前剧名——今天进项目后 5 项全部失去高亮，用户不知道自己在哪部剧。

### 2.3 剧空间内部骨架 = 阶段条驱动（四阶段）

```
① 投料 → ② 分析 → ③ 规划 → ④ 出片
```

**不是五阶段**：原设计语言的「包装 + 导出」合并进 ④。理由是 v1 明确不做生成前预览、包装参数走默认+覆盖，撑不起独立阶段；且拆成五段会让「包装」成为一个只有一行字幕预设选择的空壳页。

**五环与四段不是同一套东西**：§1 的循环是**产品主循环**，跨页面承载——「新增项目」落在剧库的导入入口（建剧动作，不属任何单剧阶段），「质检挑片」落在成品库（跨剧动作）。剧空间四段只覆盖单部剧内部可线性推进的部分。

**阶段条硬约束**：
- **只读可跳，阶段条内不放任何编辑器**。不得出现时间线段拖拽、旁白文案改写——那会滑回已被否决的「方案片段手动调整」非目标。
- 左栏素材列表**仅阶段 ①② 出现**；③④ 收起让位主区（80 集列表在规划与出片阶段是噪音）。

## 3. 全局状态语义

### 3.1 阶段条四态

| 态 | 色 | 判据 |
|---|---|---|
| 未开始 | `text/tertiary` | 无该阶段产物 |
| 进行中 | `status/info` | 有运行中的关联 job |
| 完成 | `status/success` | 产物齐备 |
| **已过期** | `status/warning` | 上游产物时间戳晚于下游（`analyzed_at` vs plan 快照；或素材增删后未重跑） |

「已过期」必须存在且显眼：整剧规划依赖全剧分析，分析重跑后旧方案即刻失效，今天界面对此毫无表示。

### 3.2 色彩纪律

- **#FF4D4F 只给钩子语义**，不可挪用。失败用 `status/error #F87171`，注意/降级/过期用 `status/warning #FBBF24`，进度用 `status/info #60A5FA`。
- 角度名固定用 `status/warning` 金（它既非状态也非钩子，用金色系与钩子红彻底区隔）。
- 每屏 primary 按钮**至多 1 个**（DSS §3.1）。

### 3.3 静默禁止清单（本次重规划的贯穿要求）

以下五类事件**必须在界面可见**，不得只进日志：

| 事件 | 今天 | 规格里的位置 |
|---|---|---|
| LLM 成稿失败 / 未配置（无规则退路） | 仅 warn 日志后静默出一版规则编排 | 该条方案标失败 + 队列页逐条 `error` 原文与「重掷此条」入口 |
| 跨集输入按配额摘录、后段集未进上下文 | 完全无声 | 阶段③ 顶部常驻一行「本次规划覆盖 80/80 集」或金色告警 |
| 参数未生效 | 改了没反应 | 字幕预设由正确性方案 A2 真正接通；输出四键接线前排「当前未生效」help（C4） |
| 单集分析失败 | 与未分析同形 | 素材行三态 + 剧卡「卡在：第 3、17、44 集失败」 |
| 未检测到原字幕位置 → 回退固定底部遮罩 | 完全无声（今天根本没有检测） | 阶段④ 包装区显式标注「未检测到，使用默认位置」（见 §10） |

### 3.3.1 降级裁决表（P-1.5 定案）

> **裁决口径**：改变观众所听所见内容的降级一律禁止（抛错，失败粒度=单条方案）；只改变成本或可用素材的降级允许，但必须留痕。

| 降级点 | 位置 | 裁决 | 理由 |
|---|---|---|---|
| 解说文案 → 硬编码模板池 | `modes_w5._CROSS_NARRATIONS`、`modes_w8.narration_texts_for`、`modes_p2` 两模式、`pipeline.intro_text` | **禁止 → 抛错** | 成片"说了什么"被换成一句假话，是质量本体的塌方 |
| 剧本驱动失败 → 规则编排 | `pipeline.build_from_script_dialogue`（死）、`script_driver` 返回 `None`、`api/narration._generate_one` 回落 `build_plan` | **禁止 → 抛错** | 同上，且失败会伪装成"这个模式本来就是这版" |
| TTS 单段失败 → 该段回退原声 | `pipeline.synthesize_narration_texts` | **禁止 → 抛错** | 半条旁白的片子不可交付；失败粒度=单条方案，不整批停摆 |
| `amix` 默认归一化把音量砍半 | `encoder.cut_segment_args` | **禁止 → 关掉归一化** | 声明的 0.2/0.12 是假的，响度失控无人负责 |
| 口味层 LLM 选题失败 → 题材静态映射 | `script_driver`（现）/ `resolve_run_style`（后） | **允许，但必须留痕** | 兜底值仍是人写的风格指令，不是假文案 |
| 分析层 LLM → 关键词打分 | `semantic/conflict.py`、`genre.py` | **允许，界面必须可见** | 影响选段而非文案；可见性归 §3.3，界面在 P-3 |
| CUDA → CPU | `analysis/transcriber.py` | **允许** | 同结果，只慢 |
| 下载多源降级 | `model_manager/downloader.py` | **允许** | 同一个文件 |
| 同名 `.srt` 缺失 → 库内 ASR 保护区 | `encoder.export_plan` | **允许** | 两个都是保护区来源，等价 |
| `raw_clip` 冲突分不足 → 放宽取全部场景 | `modes.build_raw_clip` | **允许** | 素材可得性问题，不改变观众听到的内容 |
| `ass` 路径跨盘 → 双转义保底 | `encoder._escape_filter_path` | **允许，但记为已知缺陷** | 工程兜底；真正的修法在 Backlog（跨盘转义脆弱性） |

**完整性规矩沿用 §11**：每次新增降级点必须在本表加一行并填裁决，缺裁决即视为未裁决。

### 3.4 危险操作统一规则（跨页）

批量工具最容易发生的事故是误删，而本规格新开了三处删除口：删剧（分析记录全丢）、批量删成品、清空工具箱产物。统一规矩：

1. **确认框必须量化**：显示"删除 N 条 · 共 X GB"，不允许只写"确定删除吗"。
2. **删除默认可恢复**：成片与封面删除一律移入 `<data>/.trash/<日期>/`，由「关于 → 本地数据」入口可达；只有"清空回收"才是真删除，且它自己再要一次量化确认。
3. **删剧单独对待**：它是唯一会连带丢掉分析成果与编排方案的破坏性动作，确认框必须写明"源视频保留，但 N 集的转写与 M 条方案将不可恢复"。
4. 不可撤销动作一律用 `danger` 按钮样式（DSS §3.1），且同一屏不出现第二个 primary/danger。

## 4. 逐页规格

### 4.1 工作台 `/`

**目的**：回答"今天该干什么"。
**结构**：主区 = 今日待办卡（首要）+ 3 统计芯片（剧数 / 在跑条数+ETA / 成品数+周增）+ 最近成品 6 条钩帧缩略 + 继续上次；右栏 = 环境就绪度 + 工具箱 + 快速上手。
**待办必须是可执行动作，不是通知**：每条右侧 ghost 链接直达处理位置。待办来源：分析失败集、已分析未规划的剧、队列中的失败任务、上游任务清单里长期停滞（有素材无成品）的剧。
**空态**：无剧时主区整块替换为「新增项目」引导；禁止今天 `/projects` 那种 `projects=[]` 渲染成空白网格的无空态情况。
**删除的假文案**：「导入短剧后自动预筛」「短剧素材也可以拖进来」「AI 自动预筛与全量分析」——前者改口为「逐集转写与冲突分析」，拖放为纯虚构，删。

### 4.2 剧库 `/dramas`

**目的**：一眼看清 N 部剧各自的进度与卡点。
**剧卡内容**（固定结构，全部同构）：封面（首集钩帧）· 剧名 · 四阶段微缩状态条（✓ / ! / ● / —）· 卡点文案 · meta 行（集数 · 时长 · 成品数）。
**必须新增**：搜索、按阶段/失败筛选、按最近/成品数排序。
**空态 = 首启三步（不是"还没有项目"）**：新装机同时缺 ASR 模型、LLM 凭据与任何剧，而旧的"快速上手"假文案正在被删除，删完必须补上真引导。空态整块显示三步与各步完成度：① 装 ASR 模型（未装则按钮跳 `/engines/asr`）② 配 LLM（**解说类模式必需**：七个解说模式的文案由编剧模型产出，未配置则这些模式逐条失败并说明原因，
   仅「纯原片剪辑」「字幕金句流」不依赖 LLM）③ 新增项目（选目录）。已完成的打绿勾，未完成写明还缺什么。
**卡片点击 = 直跳该剧当前阶段**（不是固定跳分析页），依赖 `project.list` 返回阶段聚合。
**「任务名称」即文件夹名**——上游是按任务派片的，所以剧库的考核视角应当是"这批我做完几部"，而不是"我建了哪些剧"。落到界面上一句聚合即可：**35 部 · 已出片 12 · 待规划 8 · 有失败 3**。
**新增项目**（primary，本页唯一主按钮）：**一次可选多个目录 → 批量建项目**（一部剧 = 一个文件夹；今天只能单目录，是批量操盘的第一道卡点）。剧名默认取文件夹名，与片单「任务名称」天然对齐，无需手输、无需任何额外录入。
**追加素材**：向已有剧补集（今天只能删项目重建，分析记录全丢）。

### 4.3 剧空间 `/drama/:id`

**常驻骨架**：剧头（标题 + meta + 右侧「还原默认」「继续投料」）→ 阶段条（四态，可点跳）→ 主区 → 底部操作栏。
**参数机制**：项目级参数（K / 风格 / 字幕预设 / 时长档）沿用**默认 + 覆盖**，改动存 `project.settings`，有「还原默认」按钮。

**① 投料**：素材列表（勾选 / 拖拽排序 / 逐行三态 / 单集重试）+ 追加素材 + 缺音频轨告警（`⚠ 3 集缺音频轨，无法转写 · 查看清单`）。**不做下载、不做网盘对接**——进到这一页时素材已在本地，这是产品边界。

**② 分析**：上半两张并排卡——轻量预筛（纯 FFmpeg，每集 1-3 秒，四项信号 0-100 分）与精准转写（ASR + 场景 + 音频 + LLM 语义，显示单集耗时与全剧预计耗时）。
**转写档位三选（本规格的硬要求）**：`全部精转（默认推荐）` / `仅推荐集精转` / `未精转集走粗档（低精度 ASR，保证集集有表示）`。
选「仅推荐集精转」时必须显示金色告警：**整剧规划需要全剧视野，仅精转 58 集会使第 59-80 集对模型不可见**。这是既定模型的内在矛盾（规划要求全剧覆盖 vs 预筛天性筛除），界面必须把它摆到台面上让操盘手显式选择，而不是替他默默牺牲后段剧情。
下半：逐集冲突强度曲线 + 转写行内编辑 + `重跑语义（不重转写）`。行内编辑的提交规则要修：今天只有回车提交、失焦静默丢弃。

**③ 规划**：**先选模式（九模式多选，卡同宽同构）与 K，再产出方案**——模式必须在规划前确定，否则"K 条角度"不知道是为哪些模式规划的（本规格自查纠正的一处漏洞：原稿把模式多选放在阶段④，会让 ③ 的产物与最终提交的模式脱节）。
选定后出 K 条卖点方案卡，**只读**。每卡四要素：角度名（金）· 取材集区间 · 钩子首句 · 模型自选理由。加一条**角度间取材重叠率**（阈值 60%，超阈值直接不出该角度）。
**这四样必须展示的理由**：用户不能挑角度（已由用户定案，角度归模型），因此只能靠这四项判断"K 条是否真是 K 个不同卖点"，重叠率是防 K 变成老虎机的安全阀。
可做的动作只有三个：`重掷此条`、`整组重规划`、`改方案数或模式`（三者都会使当前阶段产物进入「已过期」）。
**顶部常驻覆盖度行**：`本次规划覆盖 80/80 集`（或金色告警说明实际只见到前 N 集）。

**④ 出片**：只做包装与提交，**不再重复模式选择**。包装区 = 解说风格 / 字幕预设 / **原字幕处理三档（`自动避开（默认）` / `遮罩` / `不处理`，见 §10）** / 连载模式开关（**提交时参数，不写入 `project.settings`**，与 K 的持久化性质不同）+ 右侧**成本预估卡**（成片条数 / 预计耗时 / LLM 成稿次数 / 配音段数 / 占用磁盘）→ 唯一 primary `开始出片 →`，**提交后自动跳队列页**（不原地假装进度）。
条数按模式族分别算：**解说类 = K，规则类 = 全剧 top-K 冲突窗**（两者不同源，已由用户定案）。

### 4.4 队列 `/queue`

**目的**：跨剧全局任务可见可控。这页的第一能力**不是进度条，是降级留痕**。
**层级**：任务组（剧 × 模式）→ 组内逐条方案。组级显示聚合进度与 ETA，可 `暂停组` / `取消`；条级显示状态与 `重掷` / `重试`。
**必显示**：失败条的 `error` 原文（如「编剧 LLM 未配置 / 成稿超时，本条文案未产出」）与「重掷此条」入口——P-1.5 之后不存在"走规则降级的成片"这一档可展示状态，降级被失败取代，界面就不该再留降级的形状。今天这类信息只在日志里。
**筛选**：`只看失败`（默认视图之一）。失败条必须能就地看到 `error` 原文与「查看日志」。
**并发**：显示当前并发数（取 `hardware.max_parallel_jobs`）并允许页内调整。
**角标**：导轨项 + 状态栏各显示运行中条数，离开本页也能感知。
**今天这页是纯新增，且它依赖的后端不存在**：全局只有 `analysis.status`，prescreen / produce / export / model_download 任务掉线后无从查询。

### 4.5 成品 `/works`

**目的**：**质检挑片**——这是每日真瓶颈，也是工具真正能赢的地方。发布环节不介入（用户定案：不做发布闭环）。
**组织方式**：**按剧分组 + 组内网格**（用户定案 A）。一级标题为剧名 + 条数，组内平铺成片卡。
**成片卡**：逐片钩帧封面（今天 9 条同剧片共用一张项目封面，视觉上无法分辨）· 角度名 · 模式与取材集区间 · 时长/体积 · 自检结论徽章。
**自检结论徽章**：时长达标 / 含配音 / 无静音段 / 无长冻结帧。四项由 `verify_modes.py` 的度量搬到服务侧成为产品能力（时长预算、`mean_volume > -70dB`、`freezedetect < 2s`、音轨存在）。
**诚实原则**：**四项度量落地前，徽章显示「—」，不显示绿勾**。未验证的东西不能发通行证。
**批量与单片动作**：多选 → 打开所在文件夹 / 复制到指定目录 / 删除；单片 → 预览、重命名、显示完整路径（今天界面从不显示 `output_path`）。
**删除的能力**：发布包按钮、manifest 导出、LLM 标题/简介生成（随发布闭环一并取消）。
**保留在成品库的追溯**：每条片可跳回其方案卡与源集区间——质检时发现剧情不成立，要能立刻定位是哪条角度、取了哪几集。

### 4.6 引擎 `/engines`、设置 `/settings`

沿用既有定案，本次只动三处：设置页新增「生产线默认值」分区（K 默认、时长档、风格默认）；输出四键接线前标注「当前未生效：成片固定 1080×1920」；**连通自检复用已存在的 `engine_configs.test`，不再新造 `settings.test_*`**（本规格原稿在此写了三条新方法，属重复造轮子，见 §11）。`engine_configs` 已声明 `llm/tts_cloud/asr_cloud/image/video` 五个域却**无任何消费者**，所以真正的工作是把消费端接过来，而不是再造一套配置面。
**TTS 引擎仅两项**（OpenAI 兼容 + Edge 兜底）、**视觉模型凭据留空即继承文本凭据**——两条既有铁律不变，不在本次范围内改动。

### 4.7 工具箱 `/tools`

**目的**：把已有引擎以**单发小工具**的形式开放出来——不建项目、不走完整流水线，随取随用。七个工具里**六个直接复用现成引擎**、后端几乎零新增，这是它便宜的原因；也正因如此，它最容易长歪成第二套管道，故先立规矩。**唯一例外是图片生成**，需新引一类图像模型。

**三条隔离规矩（硬约束）**：
1. **不建项目、不写 `projects` / `episodes` 表**——否则剧库会被临时试转的文件污染；
2. **不共用主流程的 job 语义**——单发工具走轻量同步返回或独立 job 类型，**不进 `/queue` 的任务组**；
3. **产物只落 `data/toolbox/<日期>/`**，与 `data/outputs/` 分开，可整目录清空而不伤及成品。

| 工具 | 输入 → 输出 | 复用的引擎 |
|---|---|---|
| **转写取稿** | 任意视频/音频 → 带时间戳文稿 / SRT / 纯文本，可复制可下载 | `analysis/transcriber.py` ✓ |
| **文案转字幕** | 文案 + 总时长 → ASS / SRT（可选预设样式） | `subtitle/ass_generator.py` ✓ |
| **配音合成** | 文本 + 音色 → mp3 / wav，可调语速 | `tts/factory.py` ✓ |
| **抽帧取图** | 视频 + 时间点（或自动钩子帧）→ PNG / JPG | `infra/ffmpeg/cover.py` ✓ |
| **媒体体检** | 一批文件 → 容器/编码/分辨率/帧率/**有无音轨**/时长 报表 | `infra/ffmpeg/probe.py` ✓ |
| **对标拆解** | 竞品爆款片 → 分镜切点 + 台词 + 能量曲线 + 钩子位置图 | ASR + `scene_detector` + `audio_analyzer` ✓，**零新模型** |
| **图片生成** | 文生图（提示词）+ **图生图（参考图）** → PNG / JPG | **需新增图像模型**——本清单里唯一要新引一类模型的能力 |

**为什么是这六个 + 一个**：前四个是你点的三类加一个抽帧；**媒体体检**补的是真实痛点——网盘下来的素材常是 mkv / ts / HEVC 甚至无声版，这是素材落地后的第一道关，纯 ffprobe 零成本；**对标拆解**让"拆对标"第一次被工具化（现在都是拿剪映逐帧拖），且它是数据飞轮唯一不依赖平台回填的入口。**图片生成**是七个里唯一要新模型的，见下。

**图片生成 与 封面生成器：两个都做，但不是重复**

- **图片生成（工具箱）** = 通用素材工厂。文生图出装饰底纹、账号头图、宣传位、氛围图；**图生图出参考图变体**——给一张图，回一张构图相近的。
- **封面生成器（成品库 + 剧空间④）** = 图片生成的**下游消费者**，不是另一套能力。默认路径是"真实钩子帧打底 + 字卡排版"；要风格化时**调用图生图，参考图就是那一帧**。
- **为什么封面默认仍走真实帧**：切片封面必须与剧情对得上，纯文生图封面会误导观众，并撞平台"封面与内容不符"的限流。图生图在封面这条线上的正确用法是**以真实帧为参考**，不是凭空画一张。

**⚠️ AI 标识硬约束（不是可省的合规装饰）**：《人工智能生成合成内容标识办法》（四部门发布，**2025-09-01 施行**）第四条要求对生成的**图片**添加**显式标识**；第六条要求**传播平台核验元数据**、缺失时加提示并可要求声明；第九条的"用户主动要求不带标识"例外，前提是**服务提供者记录告知**。落到界面就是三条：

1. 图片生成的产物**默认同时带可见"AI 生成"角标 + 写入文件元数据的隐式标识**；
2. 关掉显式角标必须二次确认并留痕（对应第九条的记录义务），且写明"平台可能拒发或自行二次加标"；
3. **封面经图生图重绘后同样适用**——重绘属生成合成，不因"打底是真实帧"而豁免。这条会实打实影响封面观感与点击，是真实取舍，请在实施前确认接受。

**与引擎页的分工**：`引擎` 页的 `engine_configs.test` 只验连通性（3 秒试听、样例转写一行）；工具箱出**成品文件**。两者共用同一份配置，不重复录入。

### 4.8 关于 `/about`（渲染为覆盖层）

**形态**：导轨下组第 8 项，点开为**居中小弹窗（约 640×460）**，不是整页。理由：它没有列表、没有状态、没有二级导航，做成页面要为它配一整套 PageShell/PageHeader。URL 仍给 `/about` 便于深链与从"检查更新"跳转，但渲染为覆盖层，Esc 或点遮罩关闭。
**硬约束**：**永不自动弹出**（不在首启、不在更新后弹），只能主动点。更新提示仍走既定的"状态栏提示 + 安装/稍后"。

**布局**：左栏 190px 品牌与两张码，右栏四块信息，底部一行版权。

| 块 | 内容 | 为什么放这儿 |
|---|---|---|
| **品牌** | Logo + 名称 + 一句话定位 + 公众号二维码 + 打赏二维码 | 你要的三项。码按 ADR-009 放 `resources/about/`，**不做远程拉取**（本地优先、无云账号），代价是换码必须发版 |
| **版本** | 应用版本 · Python 服务版本 · 构建日期 · `检查更新` | 今天 app 版本与 service 版本散落在工作台；手动检查更新需要一个固定落点（既定方案不弹窗，故入口在此） |
| **本地数据** | 成品目录 / 数据与数据库 / 模型目录 / 日志（含 LLM 留痕），**每项带「打开」** | 极高性价比：今天用户根本不知道成品和数据在哪（成品一度还落在 `cache/`），而主进程已有 `revealInFolder` 可直接复用。自助排查全靠这块 |
| **开源许可** | Electron / React / AntD / FFmpeg / PySceneDetect / OpenCV / faster-whisper / edge-tts / Kokoro / 随附字体的许可证清单 | 分发的是含第三方二进制与字体的安装包，许可清单是发版应有项；也正好接住"排除 NC 授权模型"那条模型许可红线 |
| **授权与合规声明** | 素材授权责任由使用者承担；本软件不代为取得或证明授权，不提供绕过平台原创性检测的能力；媒体处理全部在本机完成、素材不上传 | 在 185 万判例的环境下这几行字对作者是实际保护，且与既定"不以外传去重为卖点"一致（见 `project-compliance-red-lines`） |

**不做**：内嵌网页、反馈表单、使用数据统计、启动弹窗。

## 10. 画面通道（正式立项，批次 2）

**现状（本轮核实）**：

- **v2 没有任何画面理解。** 分析层只有 ASR 转写、场景切换密度、音频能量；语义层 `conflict` / `genre` / `ranker` 全部吃文本。全服务 `cv2` / `opencv` / `face` 零命中，`pyproject.toml` 未声明 opencv。**没有一帧画面进过模型。**
- `docs/service/02-引擎设计.md` 里登记的 `face_detector.py`（"人脸+表情 P1"）与 `quality.py`（画面质量）**文件不存在**，是 v1 迁移到 v2 时留下的设计幽灵。留着它会让人误以为系统看得见画面——须从设计文档清除。
- `engines/subtitle/mask.py` 全文即三个常量：`_Y_OFFSET=0.88 / _HEIGHT=0.12 / _OPACITY=0.6`，`drawbox` 宽高另写死 1080/1920，**无任何检测**。而 `docs/01-技术方案-原案.md:1707` 的风险表早已写下"原片字幕区域不固定 → 遮罩位置不准 → **应对：ASR 辅助检测字幕区域**"——缓解方案从未实现，只有兜底理由进了代码并被当成设计。

**立项理由**：这不是补一个装饰功能，而是**给产品装上眼睛**。当前所有"这条片子好不好看"的判断都建立在台词与切镜密度上，短剧最贵的信息（打斗、亲吻、亮身份、表情反转）完全不在输入里。

**首个用例（低成本、独立有价值，不必等认知层）**：原字幕带定位。

1. **三层要分清，成本完全不同**（本轮核实）：
   - **传统 CV（OpenCV）—— 已免费在手**。`cv2 5.0.0`（113MB）已随 `scenedetect` 的 `opencv-python` 依赖装进环境，也已在 1.1GB sidecar 里；`opencv<5` 那条约束属 v1 视觉模块，已作废。**清晰度（拉普拉斯方差）、过曝/欠曝、运动幅度、以及"高对比水平文字带"的 y 轴投影候选，全部零新增依赖、CPU 毫秒级。**
   - **OCR —— 不做**。paddleocr/easyocr 要再加包体与一张依赖准入审批，而字幕带位置在一部剧内几乎恒定，不需要逐字识别。
   - **VLM —— 唯一能回答语义的一层**。"这块带是内嵌字幕、还是台标/花字/弹幕贴纸"、"这段画面是打斗、亲吻还是亮身份"，只有它能判。走 ADR-005 统一 OpenAI 兼容协议。
2. **字幕带定位用混合方案，不用单 VLM**：`engines/semantic/subtitle_probe.py` 先由 OpenCV 在抽出的帧上做水平投影 + 边缘密度，得到**候选带列表**（便宜、可逐帧）；再把候选带裁片交 **一次 VLM 调用**判定性质（字幕 / 台标 / 花字 / 无）。结果 `{present, band_y_start, band_y_end, kind}` 缓存进 `episode_analysis.subtitle_zone`（JSON 列，同 `audio_features` 模式）。
   **为什么必须混合**：纯启发式在漫剧上会大量误判——花字、标题卡、台标同样是"高对比水平文字带"，而你的片单 33/35 是漫剧，误判率不会是小事；纯 VLM 逐帧问则慢且贵。OpenCV 收候选、VLM 定性，各干自己擅长的部分。
3. 消费端三档（项目级默认+覆盖，见 §4.3 ④）：`自动避开`＝我们的 ASS 放到检测带之外（顶部安全区），**优先于遮盖**——竖屏压一条半透明黑带本身就伤观感；`遮罩`＝drawbox 用检测到的真实 y；`不处理`＝原样。**对漫剧「不处理」是常态档位而非兜底**。
4. 检测失败或未配视觉模型 → 回退底部 12%，但界面必须写明"未检测到，使用默认位置"（已入 §3.3 静默禁止清单）。
5. 顺手修 `drawbox_filter` 里写死的 1080/1920（与 encoder 的 `OutWidth`/`OutHeight` 重复定义）。

**后续复用（批次 3 起）**：同一条通道直接支撑画面高光（构图/动作/情绪表达）、竖屏重构图、成片自检的"画面到底好不好看"。也就是说批次 3 的认知层不必再另起一次视觉接入。

**归属批次 2 而非 3 的理由**：字幕定位自身就有独立价值，且与云端 ASR、繁简归一同属"输入与呈现的地基"，三者一次接完，不必等认知层设计定案。
