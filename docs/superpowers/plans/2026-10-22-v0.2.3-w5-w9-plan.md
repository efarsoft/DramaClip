## W5 · B-2：关键词强调字幕

### 5.1 目标

解说关键词在字幕轨上视觉强调——观众扫一眼就能抓到本条解说的记忆点。

### 5.2 方案

- **关键词来源**：方案卡已有的 `angle`（卖点角度名）与 `hook`（钩子句）——从 `plan_data.narration_texts` 中标记 `hook_id` 集合，提其文本中的核心词（2-4 字名词/动词短语），不需要额外 LLM 调用。
- **强调方式**：ASS 字幕的内联标签 `{\c&H色值&}` 改色 + `{\fscx110\fscy110}` 放大。色值从 theme accent 色（#9B7BFF 紫）派生，写死在 encoder 常量里（ASS 是纯文本不需要 token 系统）。
- **作用范围**：只影响 `subtitle_burner` 生成的烧录字幕；源硬字幕擦除后的贴底字幕不受影响（那走不同通道）。

### 5.3 实施

1. `narration_texts` 的 `text` 中提取关键词：正则匹配 2-4 字中文实体（人名/地名/动作短语），匹配集来自本集 `angle` 字段的分词。
2. `subtitle_burner` 回调里对含关键词的行注入 ASS 内联标签。
3. 测试：有关键词行 → ASS 含强调标签；无关键词行 → 原样。

### 5.4 边界

- 不改源硬字幕擦除后的贴底字幕（那是 OCR 通道，走 subtitle_source='original'）。
- 不加新设置键——强调是全局默认行为，要关属于美化偏好不是功能开关。

## W6 · B-1：开场 3 秒质检 + 转场音效

### 6.1 开场质检

**方案**：进 `export_audit.py` 审计链，导出完成后探测成片前 3 秒的音频响度。

- 探测方式：ffmpeg `astats` 或 `volumedetect` 取前 3 秒 RMS；RMS < 阈值（-50dB）= 无声。
- **无声 ≠ fail**：纯剪辑模式（raw_clip 等）可能开场确实只有画面——此时**留痕不拦片**（规格 §1.2 同款纪律）。
- 解说模式（full_narration 等）开场无声 → `_note_degraded` 留痕「开场 3 秒无人声，钩子可能站不住」+ **钩子重掷建议**写入 degraded_notes。

**不做**：自动重掷钩子——那需要回到规划层重跑 LLM，导出层不应该触发 LLM 往返。

### 6.2 转场音效

**方案**：场景切换点（`TimelineSegment` 的 `audio` 字段从 `original` → `narration` 或反向变化处）插入短转场音效。

- SFX 资产：3 条 whoosh（短/中/长），随包在 `resources/sfx/` 目录，文件 <100KB。
- 混音方式：ffmpeg `adelay` + `amix`，音量 -12dB（让位 BGM/人声）。
- 设置键：`export.transition_sfx`（默认 false，用户显式开启）。
- 可关：设置关掉后不混 SFX，不影响成片。

**边界**：只在场景切换（`audio` 通道变化）时插 SFX，同通道内段间不插——观众不会感觉到每句旁白之间都有嗖的一声。

### 6.3 测试

- 开场质检：无声成片 → degraded_notes 含钩子建议；有声成片 → 无降级。
- 转场音效：有 SFX 资产时 → 混音输出含 SFX 音轨；设置关 → 不混。

## W7 · B-3：BGM 节拍卡点

### 7.1 方案

librosa onset 检测 BGM 节拍 → 场景切换点吸附最近节拍。

- **前置**：librosa 已在 ml extra（零新依赖）。
- **吸附规则**：场景切换点 ±0.5s 内有 onset → 吸附到 onset；超出容差不硬掰（叙事节奏优先于卡点）。
- **触发条件**：`export.bgm_snap` 设置键（默认 false），开启后才跑 librosa 分析。
- **作用对象**：只影响场景切换的时间戳（`TimelineSegment.start`），不改旁白/台词时间戳。

### 7.2 实施

1. BGM 文件用 librosa.load 加载（只取 onset envelope，不全谱分析）。
2. `librosa.onset.onset_detect` → onset 时间戳列表。
3. 场景切换点在容差窗内 → 吸附到最近 onset。
4. 吸附后如有段重叠 → 放弃吸附（叙事安全第一）。

### 7.3 边界

- 只吸附场景切换点，不改旁白/台词/钩子的时间戳。
- 无 BGM 或 librosa 分析失败 → 静默跳过（不留痕——这是增强项不是降级）。

## W8 · B-4：发布数据回流 MVP

### 8.1 方案

成片详情页新增「发布数据」录入区（平台/链接/播放/完播/点赞手录）→ `export_jobs` 新列 JSON → 成片列表展示数据列。

1. 迁移 `026_publish_data.sql`：`export_jobs` 加 `publish_data` TEXT 列（JSON）。

## W9 · B-5：人脸 9:16 裁切（**已裁决关闭，不实施**——2026-10-23 业主裁决）

spike 不再执行，直接关项。裁决理由（三条产品事实 + 一条市场事实）：

1. **竖版裁切是分发端工作**：抖音/快手上传横版视频时自带平台级智能裁切，
   自研的边际收益只剩「省掉平台二次处理」。
2. **解说成片的主体是解说不是画面重构**：观众消费解说+字幕+佐证画面，
   画面重构对完播的贡献远小于文案与节奏（与「时长让位于质量」裁决同向）。
3. **素材形态对裁切不友好**：真人短剧中远景+双人对话为主，9:16 裁切是信息
   削减操作，裁错人比不裁更糟。
4. **素材市场向漫剧/AI 剧迁移**（业主观察）：构图天然偏竖版/方形甚至直接生成
   竖版素材，横版人脸裁切的需求根基本身在萎缩。

**留档备选**（不立项）：若未来素材形态真有竖版硬需求，「固定居中裁切+导出时
可选 9:16」是零 AI 成本的低配替代（约一天），不需要人脸检测。
