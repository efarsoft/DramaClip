## 第一章 项目概述与技术选型

### 1.1 项目定位

DramaClip 是一款本地优先的短剧自动高光剪辑工具，面向短剧推广达人（短剧CPS从业者）。核心能力：导入短剧视频 → AI智能分析 → 自动生成多种风格的推广短视频。

### 1.2 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 桌面框架 | Tauri 2.x | 替代Electron，包体更小，内存占用更低 |
| 前端 | React 19 + TypeScript 5.7 + Vite 6.x | UI框架 |
| UI组件 | Ant Design 5.x | 组件库 |
| 状态管理 | Zustand 5.x | 轻量状态管理 |
| 后端宿主 | Rust | Tauri后端，负责进程管理、任务调度、视频编码 |
| AI/ML服务 | Python 3.10+ | 独立进程，承载所有ML推理任务 |
| 进程通信 | Unix Domain Socket + JSON-RPC 2.0 | Rust ↔ Python |
| 视频处理 | FFmpeg（libavcodec/libavfilter） | 解码、滤镜、编码 |
| 数据库 | SQLite | 项目状态持久化 |
| ASR | faster-whisper / SenseVoice | 离线语音识别 |
| TTS | IndexTTS-2 / Kokoro / Edge-TTS | 解说音频合成 |
| LLM | 本地小模型(7B/14B) + 云端API可选 | 语义分析、文案生成 |

### 1.3 为什么选 Tauri 2.x

| 对比项 | Electron | Tauri 2.x |
|--------|----------|-----------|
| 安装包体积 | 150-300MB | 10-30MB |
| 运行时内存 | 200-400MB | 50-100MB |
| 原生能力 | 依赖Node.js | Rust原生，性能更强 |
| 视频处理 | 需调用外部进程 | 可直接集成FFmpeg |
| 进程管理 | Node.js子进程 | Rust原生进程管理，更稳定 |

### 2.2 进程通信架构

```
Rust 主进程 ←── Unix Domain Socket ──→ Python ML Service
                 (JSON-RPC 2.0)

通信方式：
- Rust → Python：请求-响应模式（分析任务、TTS合成）
- Python → Rust：进度推送（长任务的实时进度回调）
- 前端 ↔ Rust：Tauri invoke/event 机制
```

### 2.3 Python ML Service 进程管理

```
应用启动 → ServiceManager 启动 Python 进程
         → 健康检查（心跳探测）
         → 就绪后建立 Socket 连接
         → 接收前端任务 → 转发给 Python → 返回结果

异常处理：
- Python 进程崩溃 → 自动重启 + 任务重入
- 内存超限 → 主动回收 + 模型卸载
- 应用退出 → 优雅关闭 Python 进程
```

## 第三章附 两阶段分析策略（轻量预筛 + 精准ASR）

### 3附.1 设计背景

短剧通常多集（5-100集），如果每集都做完整ASR + LLM分析，耗时较长。而实际上很多集是过渡剧情，并没有高光价值。因此采用**轻量预筛 + 精准分析**的两阶段策略，减少不必要的计算。

### 3附.2 核心流程

```
阶段一（轻量预筛，秒级）          阶段二（精准ASR，按需）
┌──────────────────────┐        ┌──────────────────────┐
│ 对每集做极速特征提取   │        │ 只对高分集做完整ASR   │
│ 不做ASR，不做LLM      │        │ + LLM语义分析         │
│                      │        │                      │
│ 检测项：              │  ──→   │ 触发条件：            │
│ - 音频能量峰值        │        │ - 预筛分≥阈值         │
│ - 场景切换密度        │        │ - 或用户手动指定       │
│ - 人声活跃度          │        │                      │
│ - 画面运动幅度        │        │                      │
│                      │        │                      │
│ 耗时：每集1-3秒       │        │ 耗时：每集5-15秒(GPU) │
└──────────────────────┘        └──────────────────────┘
```

### 3附.3 集数阈值规则

| 条件 | 行为 | 理由 |
|------|------|------|
| 集数 ≤ 15集 | **跳过预筛，直接全量分析** | 集数少，预筛的筛选价值低，直接分析更快 |
| 集数 > 15集 | **先预筛，再按需精准分析** | 集数多，通过预筛过滤低价值集，节省时间 |

阈值可在设置页面调整，默认15。

### 3附.4 阶段一：轻量预筛（每集1-3秒）

不做ASR，只用计算密集型但极快的信号：

| 检测项 | 工具 | 耗时 | 说明 |
|--------|------|------|------|
| 音频能量曲线 | FFmpeg `astats` | <1秒 | 找爆点、高潮位置 |
| 音频能量峰值数量 | 简单统计 | - | 峰值多=冲突密集 |
| 场景切换密度 | FFmpeg `select` 滤镜 | 1-2秒 | 切镜多=节奏快 |
| 人声活跃度 | FFmpeg `silencedetect` | <1秒 | 对白密度 |
| 画面运动幅度 | FFmpeg `freezedetect` | 1秒 | 动作戏/静态戏 |

**输出预筛分（0-100）**：

```
预筛分 = α × 能量峰值密度 
       + β × 场景切换密度 
       + γ × 人声活跃度 
       + δ × 画面运动幅度
```

预筛分 ≥ 阈值（默认70）的集标记为推荐分析。

**80集预筛总耗时：80-240秒（1.5-4分钟），全部CPU完成，不需要GPU。**

### 3附.8 Rust侧实现

```rust
pub struct AnalysisSettings {
    pub full_analysis_threshold: i32,   // 默认 15，集数≤此值跳过预筛
    pub prescreen_score_threshold: f64, // 默认 70.0，预筛推荐阈值
}

pub struct PrescreenResult {
    pub episode_id: String,
    pub audio_peak_density: f64,
    pub scene_cut_density: f64,
    pub voice_activity_ratio: f64,
    pub motion_intensity: f64,
    pub prescreen_score: f64,      // 0-100
    pub recommended: bool,         // score >= threshold
}

impl AnalysisOrchestrator {
    pub async fn start_analysis(&self, project_id: &str) -> Result<()> {
        let episodes = self.db.get_episodes(project_id).await?;
        let settings = self.db.get_analysis_settings().await?;
        
        if episodes.len() <= settings.full_analysis_threshold as usize {
            // 集数少，跳过预筛，直接全量分析
            for ep in &episodes {
                self.analyze_episode(ep).await?;
            }
        } else {
            // 集数多，先预筛再按需
            let prescreen = self.prescreen_all(&episodes).await?;
            let recommended: Vec<_> = prescreen.iter()
                .filter(|p| p.prescreen_score >= settings.prescreen_score_threshold)
                .collect();
            for p in &recommended {
                self.analyze_episode(&p.episode_id).await?;
            }
        }
        
        Ok(())
    }
}

// 预筛只需FFmpeg命令行，不需要Python Service，在Rust侧直接调用
impl Prescreener {
    pub async fn prescreen(&self, source_path: &str) -> Result<PrescreenResult> {
        let audio_stats = self.ffprobe_audio_energy(source_path).await?;
        let scene_cuts = self.ffprobe_scene_changes(source_path).await?;
        let voice_ratio = self.ffprobe_voice_activity(source_path).await?;
        let motion = self.ffprobe_motion_intensity(source_path).await?;
        
        let score = self.calculate_score(audio_stats, scene_cuts, voice_ratio, motion);
        
        Ok(PrescreenResult {
            prescreen_score: score,
            recommended: score >= self.settings.prescreen_score_threshold,
            ...
        })
    }
}
```

## 第四章 语义理解引擎（第二层：LLM语义分析）

### 4.1 剧情结构化

输入ASR转写结果，LLM输出：
- 角色列表（姓名、身份、关系）
- 场景列表（地点、时间、参与者）
- 剧情梗概

### 4.2 冲突打分

对每个场景/片段进行冲突强度评分（0-100）：

```
冲突分 = f(台词对抗性, 情绪强度, 剧情转折度, 视觉张力)
```

### 4.3 高光排序

综合第一层信号 + 第二层语义，输出最终的高光片段排序列表：

```
高光分 = α × 冲突分 + β × 音频能量 + γ × 画质分 + δ × 情绪强度
```

### 4.4 题材分类

自动识别短剧题材（复仇/甜宠/悬疑/逆袭/家庭伦理等），用于后续策略适配。

| 3 | 全片解说 | ✅ TTS | 压低 | ✅ 旁白字幕 | 自动遮罩 | 120-300s | P1 |
| 4 | 剧情解说 | ❌ | ✅ 100% | ✅ 对白字幕 | 自动遮罩 | 45-120s | P1 |
| 5 | 纯原片剪辑 | ❌ | ✅ 100% | 原片自带 | **不处理** | 30-120s | P0 |
| 6 | 字幕金句流 | ❌ | ✅ 100% | ✅ **核心** | 自动遮罩 | 30-90s | P1 |
| 7 | 超短悬念版 | ✅ TTS | ✅ 高潮 | ✅ 旁白字幕 | 自动遮罩 | 10-20s | P1 |
| 8 | 双人对谈式 | ✅ 双音色 | ✅ | ✅ 旁白字幕 | 自动遮罩 | 60-180s | P2 |
| 9 | 角色内心独白 | ✅ | ✅ 压低 | ✅ 旁白字幕 | 自动遮罩 | 120-300s | P2 |

### 6.2 叙事逻辑定位

```
                    有AI旁白 ←─────────────────────→ 无AI旁白
                    │                                  │
    旁白为主 ──────┤  交叉解说 / 片头解说 / 全片解说     │
                    │                                  │
                    │                                  │
    原声为主 ──────┤           剧情解说                  │  纯原片剪辑
                    │    （原片对白重新编排叙事）        │ （纯画面冲突冲击）
                    │                                  │
                    │                                  │
    字幕驱动 ──────┤                                    │  字幕金句流
                         双人对谈 / 内心独白             │ （原声+动态字幕双通道）
```

### 6.3 模式一：交叉解说

**叙事逻辑**：AI旁白与画面交替出现，旁白承担"串联+悬念引导"功能。

```
┌────────┬──────────┬────────┬──────────┬────────┬──────────┐
│ 画面A  │ 解说旁白  │ 画面B  │ 解说旁白  │ 画面C  │ 解说收尾  │
│ 8秒    │ 5秒      │ 12秒   │ 6秒      │ 10秒   │ 5秒      │
│ 原声   │ TTS生成  │ 原声   │ TTS生成  │ 原声   │ TTS生成  │
└────────┴──────────┴────────┴──────────┴────────┴──────────┘
```

**混音规则**：解说段原声静音，画面段原声保留。

**字幕**：TTS旁白段叠加旁白字幕（跟随全局风格预设），原片对白段自动半透明遮罩覆盖原片硬字幕。

### 6.4 模式二：片头解说

**叙事逻辑**：开头一段解说引入 → 接正片高光画面，解说只做"引子"。

```
┌────────────────────┬──────────────────────────────────────┐
│ 片头解说（含画面）   │ 正片高光画面（纯画面+原声）            │
│ 30-60秒            │ 剩余时长                               │
│ TTS + 配合画面      │ 原声保留                               │
└────────────────────┴──────────────────────────────────────┘
```

**混音规则**：片头段解说为主+原声为辅（20%），正片段纯原声。

**字幕**：片头段叠加旁白字幕，正片段自动遮罩覆盖原片硬字幕。

### 6.5 模式三：全片解说

**叙事逻辑**：全程画面 + 全程解说旁白覆盖，类似"X分钟看完一部剧"。

```
┌──────────────────────────────────────────────────────────┐
│ 全程画面 + 全程解说旁白（解说音频轨覆盖原声）               │
│ 画面保留但原声降低至10-20%作为背景音                       │
│ TTS贯穿始终                                               │
└──────────────────────────────────────────────────────────┘
```

**混音规则**：解说100% + 原声10-20% + BGM可选。

**字幕**：全程旁白字幕 + 自动遮罩覆盖原片硬字幕。

**P2子选项**：支持切换为"角色内心独白"视角（第一人称），见模式九。

### 6.6 模式四：剧情解说

**叙事逻辑**：不用AI旁白，从原片中提取最精彩的对白片段，重新编排顺序，让原片角色自己"讲"这个故事。类似电影预告片。

```
┌────────┬────────┬────────┬────────┬────────┬────────┬────────┐
│ 原声A  │ 原声B  │ 原声C  │ 原声D  │ 原声E  │ 原声F  │ 原声G  │
│ 3-8秒  │ 5-10秒 │ 3-6秒  │ 8-12秒 │ 4-8秒  │ 6-10秒 │ 3-5秒  │
│ 冲突对白│ 情绪爆发│ 悬念台词│ 反转台词│ 金句  │ 高潮对白│ 钩子  │
└────────┴────────┴────────┴────────┴────────┴────────┴────────┘
     ↕           ↕           ↕
  可选：片段间插入0.5-1秒黑场/闪白转场
  可选：底部叠加轻BGM（音量20-30%）
```

**对白筛选逻辑**：
1. 第一遍：台词质量打分（信息密度、情绪强度、独立性、冲突性、金句潜力）
2. 第二遍：LLM按"起承转合"叙事逻辑重新编排

**混音规则**：原声对白100% + 可选BGM（20-30%），无TTS。

**字幕**：自动遮罩覆盖原片硬字幕后，叠加筛选出的对白字幕（跟随全局风格预设）。

### 6.7 模式五：纯原片剪辑

**叙事逻辑**：完全不添加任何AI生成内容，纯粹从原片中智能选取高光画面，按冲突强度编排，输出"原片精华浓缩版"。

```
┌──────────────────────────────────────────────────────────────────┐
│  纯原片画面 + 原声                                               │
│  ┌─────────┬──────────┬──────────┬──────────┬────────────────┐ │
│  │ 场景A   │ 场景B    │ 场景C    │ 场景D    │ 场景E          │ │
│  │ 冲突92  │ 冲突88   │ 冲突85   │ 冲突78   │ 冲突75         │ │
│  │ 硬切    │ 硬切     │ 叠化0.5s │ 硬切     │ 悬念黑场收尾   │ │
│  └─────────┴──────────┴──────────┴──────────┴────────────────┘ │
│  可选：底部叠加轻BGM（10-20%音量）                               │
└──────────────────────────────────────────────────────────────────┘
```

**筛选规则**：冲突分≥70 + 画质分≥60 + 单场景3-25秒 + 总时长符合目标。

**编排规则**：开场取冲突分最高场景 → 中间按原片时间线排列 → 结尾悬念/反转场景。

**混音规则**：纯原声100%，可选BGM（10-20%），无TTS。

**字幕**：**不处理原片硬字幕**，保留原片自带字幕。零加工原则。

### 6.8 模式六：字幕金句流

**叙事逻辑**：保留原声（对白清晰可闻），叠加动态特效字幕作为核心视觉元素。实现**双通道信息传递**——有声时听对白，静音时看字幕也能完整理解剧情。

```
┌──────────────────────────────────────────────────────────────┐
│  画面轨：高光场景A → 高光场景B → 高光场景C → ... → 结尾卡片 │
│                                                              │
│  音频轨：原声100%保留（对白清晰可闻）                        │
│  可选：轻BGM铺底（20-30%音量）                               │
│                                                              │
│  字幕轨（核心）：                                            │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐            │
│  │ "三年了"    │  │ "我忍够了"  │  │ "该还的"   │            │
│  │ 大字居中弹出 │  │ 震动特效    │  │ "一笔一笔  │            │
│  │ 白色描边    │  │ 红色高亮    │  │  都要算清" │            │
│  └────────────┘  └────────────┘  └────────────┘            │
│                                                              │
│  结尾：文字卡片 "结局太爽了！看全集→"                         │
└──────────────────────────────────────────────────────────────┘
```

**与纯原片剪辑的区别**：

| 维度 | 纯原片剪辑 | 字幕金句流 |
|------|-----------|-----------|
| 字幕 | 不加（保留原片自带硬字幕） | **核心元素**，动态特效字幕 |
| 原声 | 保留完整音量 | 同样保留完整音量 |
| 信息传递 | 靠画面+原声对白 | **双通道**——有声听对白，静音看字幕 |
| 适用场景 | 原片自带字幕已够用 | 原片字幕小/不清晰，或需要强调关键台词 |

**混音规则**：原声100% + 可选BGM（20-30%），无TTS。

**原片字幕遮盖**：系统自动施加半透明遮罩覆盖原片硬字幕。

**字幕呈现方式**：详见第六章附A。

### 6.9 模式七：超短悬念版

**叙事逻辑**：10-20秒的超短视频，用作信息流广告的"钩子"，把用户引到完整版推广视频或小程序落地页。

```
┌──────────────┬───────────────────┬──────────────┐
│ TTS钩子      │ 原声冲突画面       │ TTS收尾引导   │
│ 3-5秒        │ 5-10秒            │ 3-5秒        │
│ "婆婆把怀孕   │ 女主摔碗反击      │ "结局太解气   │
│  的她赶出门"  │ 原声对白高潮       │  了！点下面   │
│              │                   │  看全集"      │
└──────────────┴───────────────────┴──────────────┘
总时长：10-20秒
```

**技术特点**：
- 从冲突分排序中取Top 1片段，截取最强3-5秒
- LLM任务极简：一句话钩子 + 一句话收尾引导
- TTS调用仅2次
- 编码速度最快

**字幕**：TTS段叠加旁白字幕，自动遮罩覆盖原片硬字幕。

### 6.10 模式八：双人对谈式解说（P2）

**叙事逻辑**：模拟两个主持人聊天讨论剧情的形式，用对话推动叙事。

```
音色A（主持人）："你们看过最爽的复仇剧是什么？"
音色B（嘉宾）："我跟你说，最近有一部，女主被欺负了三年..."
音色A："然后呢？"
音色B："然后她直接甩出离婚协议，全场都傻了。"
[穿插原片对应画面]
```

**技术特点**：TTS需要两个不同音色交替合成，LLM生成对话体文案。

**字幕**：双音色旁白配字幕（用角色标注式布局区分说话人），自动遮罩覆盖原片硬字幕。

### 6.11 模式九：角色内心独白式（P2）

**叙事逻辑**：作为全片解说的**视角子选项**，用AI旁白模拟剧中某个角色的第一人称内心OS。

```
（女主视角）
"嫁进这个家三年，我以为只要我足够忍让，他们总会接受我。
 直到那天，我听到了他和她的对话……
 该还的，一分都不能少。"
```

**与全片解说的区别**：第三人称上帝视角 → 第一人称角色视角，其余编排逻辑基本一致。

### 6.12 一键全部生成

```
┌─ 共享前置（执行一次）─────────────────────────────────────────┐
│  1. 智能分析（ASR/场景切割/冲突打分/高光排序）                 │
│  2. LLM 一次性生成所有模式的文案/编排方案                      │
│  3. TTS 合成（仅模式1/2/3/7/8/9需要）                        │
└────┬────┬────┬────┬────┬────┬────┬────────────────────────────┘
     │    │    │    │    │    │    │
     ▼    ▼    ▼    ▼    ▼    ▼    ▼
   交叉  片头  全片  剧情  纯原  字幕  超短
   解说  解说  解说  解说  片    金句  悬念
                      │         │    流    版
              ┌───────┘         └───────┐
              │ 不需要等TTS              │ 不需要等TTS
              │ 分析完成即可开始         │ 分析完成即可开始
              ▼                         ▼
         与TTS并行执行              与TTS并行执行
```

**关键优化**：剧情解说、纯原片剪辑、字幕金句流三种模式不需要TTS，分析完成后立即开始编排编码，与TTS合成并行。

## 第六章附A 字幕渲染引擎（全局共享基础设施）

### 6A.1 设计概述

字幕渲染引擎是**服务于所有九种模式的全局共享基础设施**，而非某个模式的专属功能。各模式通过引用风格预设来调用字幕渲染能力。

```
┌─────────────────────────────────────────────────────────────────┐
│  字幕渲染引擎（全局共享基础设施）                                │
│  ├── 风格预设库（5套预设 + 用户自定义）                         │
│  ├── ASS生成器                                                  │
│  ├── 情绪→样式智能匹配器                                       │
│  └── 字体/颜色/动画参数管理                                     │
│                                                                 │
│  各模式调用方式：                                               │
│  ├── 字幕金句流 → 字幕是核心，必须选预设，配置项完整展开        │
│  ├── 其他带旁白模式 → 字幕是辅助，提供"字幕风格"下拉选择       │
│  │   ├── 默认：跟随全局预设                                     │
│  │   └── 可单独覆盖：为当前模式选择不同预设                     │
│  └── 纯原片剪辑 → 通常不加字幕，可选"叠加字幕"开关             │
└─────────────────────────────────────────────────────────────────┘
```

字幕的呈现效果由四个独立维度组合而成：

```
字幕呈现效果 = 出现节奏 × 动画效果 × 空间布局 × 情绪强化
```

### 6A.2 维度一：文字出现节奏

控制字幕以什么粒度出现在画面中。

| 节奏类型 | 效果描述 | 适用场景 | 技术实现 |
|---------|---------|---------|---------|
| **整句弹出** | 一句话瞬间完整出现 | 通用，最基础 | drawtext 直接渲染 |
| **逐字打出** | 像打字机一样一个字一个字出现 | 悬念台词、独白 | 按字拆分 + 逐字时间轴偏移 |
| **逐词蹦出** | 2-3个字一组，按语义节奏蹦出 | 快节奏冲突对白 | 按分词结果分组 + 节奏偏移 |
| **卡拉OK式** | 文字整体可见，逐字/逐词高亮填充颜色 | 歌词式呈现、情绪渲染 | 双层文字 + 遮罩动画（P2评估） |

**按台词类型推荐**：

| 台词类型 | 推荐节奏 | 速度参数 |
|---------|---------|---------|
| 平静叙述 | 整句弹出 或 逐字打出 | 0.08秒/字 |
| 冲突升级 | 逐词蹦出 | 0.04秒/词 |
| 高潮金句 | 整句弹出（瞬间冲击） | 瞬时 |
| 悬念钩子 | 逐字打出（制造紧张感） | 0.1秒/字 |

### 6A.3 维度二：动画效果

控制字幕出现时的运动方式。

| 动画类型 | 效果描述 | 适用情绪 | ASS实现方式 |
|---------|---------|---------|------------|
| **淡入淡出** | 透明度渐变 | 平静、回忆、温情 | `\fad(300,300)` |
| **弹入** | 从0放大到100%再回弹95% | 活泼、惊讶、转折 | `\t(0,200,\fscx120\fscy120)\t(200,350,\fscx95\fscy95)` |
| **缩放强调** | 关键词80%→120%→100% | 重点强调、冲突升级 | `\t(0,150,\fscx120\fscy120)\t(150,300,\fscx100\fscy100)` |
| **震动/抖动** | 文字轻微左右抖动 | 愤怒、威胁、震撼 | `\t(0,500,\shad1)\shad2` 配合位置偏移 |
| **滑入** | 从左/右/上/下滑入画面 | 通用转场 | `\move(x1,y1,x2,y2,t1,t2)` |
| **旋转入场** | 带轻微旋转角度出现 | 戏剧性、夸张 | `\frz` 旋转角度动画 |
| **擦除/扫光** | 从左到右逐渐显现 | 悬疑、揭露真相 | 遮罩层 + `\clip` 矩形动画 |

**按情绪类型推荐**：

| 情绪类型 | 推荐动画 | 组合方式 |
|---------|---------|---------|
| 日常对话 | 淡入淡出 | 不抢画面 |
| 质问/对抗 | 弹入 + 轻微震动 | 力量感 |
| 揭露真相 | 擦除/扫光 | 悬念揭晓感 |
| 高潮爆发 | 缩放强调 + 震动 | 冲击力拉满 |
| 结尾钩子 | 弹入 + 缩放 | "不点就难受" |

### 6A.4 维度三：空间布局

控制字幕在画面中的位置和排列方式。

| 布局类型 | 效果描述 | 适用场景 | 实现要点 |
|---------|---------|---------|---------|
| **底部字幕条** | 画面底部1/5区域 | 通用，最不打扰画面 | `Alignment=2` |
| **居中单行大字** | 画面正中央，一行大字 | 金句强调，冲击力最强 | `Alignment=5`，字号加大 |
| **居中多行堆叠** | 画面中央，多行上下堆叠 | 信息量大的台词 | `\N` 换行 |
| **顶部标题式** | 画面上方1/4区域 | 补充说明、角色名标注 | `Alignment=8` |
| **全屏铺满** | 文字占满画面，画面压暗 | 关键转折、章节分隔 | 叠加半透明黑色遮罩 |
| **左右分栏** | 左右两侧各一行 | 双人对峙场景 | 两条字幕轨 |
| **角色标注式** | 字幕旁带角色名色块 | 多人对话，区分说话人 | 色块 + 对白文字 |

**按场景类型推荐**：

| 场景类型 | 推荐布局 |
|---------|---------|
| 普通对白 | 底部字幕条 |
| 关键金句 | 居中单行大字 |
| 情绪爆发 | 居中多行堆叠 |
| 章节/时间跳转 | 全屏铺满 |
| 双人对峙 | 左右分栏 或 角色标注式 |

### 6A.5 维度四：情绪强化

通过颜色、大小、特效配合剧情情绪。

| 情绪类型 | 颜色方案 | 附加效果 |
|---------|---------|---------|
| **平静/叙述** | 白色字 + 黑色描边 | 无特殊效果 |

### 6A.9 技术实现方案

| 实现项 | 技术方案 | 说明 |
|--------|---------|------|
| 字幕渲染引擎 | **ASS字幕文件**（首选） | 动画能力最强，支持 `\t()` 关键帧动画 |
| 基础渲染 | FFmpeg `drawtext` 滤镜 | 简单场景可用，动画能力有限 |
| 逐字打出效果 | ASS `\t()` + 多行叠加 | 每个字独立一行，通过时间偏移实现 |
| 缩放/震动效果 | ASS `\fscx/\fscy` + `\t()` | 关键帧动画 |
| 颜色渐变 | ASS `\c&H` + `\t()` | 颜色过渡动画 |
| 多行堆叠 | ASS `\N` 换行 | 多行文字居中排列 |
| 风格预设 | JSON模板文件 | 四维度参数封装为JSON，一键应用 |
| ASS生成 | Rust侧生成ASS文件 | 根据预设+台词数据，程序化生成 |
| 字幕烧录 | FFmpeg `ass` 滤镜 | `-vf ass=subtitle.ass` |

**ASS字幕文件生成流程**：

```
台词数据（JSON）+ 风格预设（JSON）
    │
    ▼
Rust侧 ASS 生成器
    ├── 解析台词时间轴
    ├── 按情绪标签匹配呈现参数
    ├── 生成 Dialogue 行（每句台词一行）
    ├── 注入动画标签（\t, \fad, \move 等）
    └── 输出 .ass 文件
    │
    ▼
FFmpeg 烧录
    └── -vf ass=output.ass → 合成到视频
```

## 第八章 逐片段处理与台词保护系统

### 8.1 系统概述

本章覆盖两件事：**切点安全**（台词不被吞、画面不闪帧）与**逐片段施加的轻微处理**（变速、缩放、色彩、元数据）。数值集中在 `06-经验参数表.md` §1，实现位于 `service/dramaclip/engines/dedup/`。

> 措辞收口（2026-09-20）：本章早期版本带有把上述处理描述为针对平台内容判定的宣传性目的表述，已统一改为中性技术表述；机制、参数与滤镜链均未变化。合规裁决记录见 `docs/superpowers/plans/2026-09-12-p3-decomposition.md`，并由 `desktop/src/__tests__/copyTruth.test.ts` 的门禁长期守住。

### 8.2 静音区避让与台词防吞（Smart Jitter）

**核心原则**：绝对禁止盲切——避免纯数学随机加减导致"吞字"或"闪帧"。

```
处理流程：
1. 读取同名 .srt 字幕文件
2. 将每行字幕的 [开始-0.2s, 结束+0.15s] 标定为"台词保护禁区"
3. 当裁切点落在禁区内 → 自动向外避让（Snap）保留台词完整性
4. 当裁切点落在安静空白间隙 → 允许在物理间隙边界内进行 ±0.1s~0.3s 随机安全抖动（Jitter）
```

### 8.3 极微变速（Micro-Speed）

为每个片段施加 0.996~1.004 的随机变速，自动启用 FFmpeg `atempo` 音频滤镜做**变速不变调**处理，重编码为 AAC。区间上限取自 v1 实测：超出此幅度人耳可辨。

### 8.4 等尺寸画面微缩放（Micro-Scaling）

对画面应用 [1.2%, 1.8%] 的随机微缩放，裁切出的局部画面通过 `scale` 滤镜等比例拉伸回标准输出尺寸（如竖屏 1080×1920），保证逐片段之间无黑边、无分辨率偏差。

### 8.5 对比度与亮度微幅波动（Visual EQ）

叠加 `eq` 滤镜：对比度 [0.99, 1.01] 轻微抖动，亮度 [-0.01, 0.01] 微幅波动，幅度控制在肉眼不可辨的区间。

### 8.6 元数据不写入（Metadata）

在片段分割与最终拼接的 FFmpeg 命令中全程注入 `-map_metadata -1`，成片不携带源素材的创建时间、地理位置、设备与编码工具标签。

### 8.7 参数汇总

| 处理项 | 参数范围 | 作用 |
|--------|---------|------|
| Smart Jitter | ±0.1s ~ 0.3s | 切点避让台词，不吞字 |
| Micro-Speed | 0.996 ~ 1.004 | 变速不变调（`atempo`） |
| Micro-Scaling | 1.2% ~ 1.8% | 等尺寸回拉，无黑边与分辨率偏差 |
| Visual EQ | 对比度 ±0.01, 亮度 ±0.01 | 逐片段微幅色彩波动 |
| Metadata | `-map_metadata -1` | 不写入设备/时间/地理标签 |

这四项在编码阶段逐片段固定施加（`encoder.py` 的 `cut_segment_args`），界面当前不提供开关。

## 第十五章 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| TTS全片解说合成耗时过长 | 用户体验差 | 流式合成：边合成边送入编码管道 |
| 本地LLM质量不足 | 文案/分析质量差 | 支持云端API降级；Prompt工程持续优化 |
| GPU显存不足 | 模型无法加载 | 自动降级到CPU；提供量化版模型 |
| 字幕渲染性能 | 大量字幕拖慢编码 | ASS硬字幕烧录性能优于drawtext |
| 平台内容判定规则变化 | 推广效果波动 | 以多模式产能与内容质量应对；不针对判定规则做适配（合规红线，见第八章措辞收口） |
| 原片字幕区域不固定 | 遮罩位置不准 | ASR辅助检测字幕区域；固定底部12%覆盖绝大多数短剧 |
| 预筛误判漏掉好集 | 错过有价值内容 | 阈值可调（默认70）；用户可手动加入任意集 |

> **文档状态**：最终版
> **核心设计决策汇总**：
> 1. 字幕风格预设为**全局共享基础设施**，所有九种模式均可引用，不是某个模式的专属功能
> 2. 原片字幕遮盖采用**半透明遮罩自动覆盖**，纯原片剪辑不处理，用户无需任何操作
> 3. 逐片段处理以**台词零损伤**为前提：Smart Jitter 保证切点不吞字（见第八章）
> 4. 一键全部生成时，不需要TTS的三种模式（剧情解说/纯原片剪辑/字幕金句流）与TTS合成**并行执行**
> 5. **两阶段分析策略**：集数≤15直接全量ASR，>15先轻量预筛再按需精准分析；预筛阈值和全量阈值均可在设置页面调整
> 6. 每集ASR结果**独立持久化**到数据库，已分析的集不重复分析，支持分批导入增量分析
