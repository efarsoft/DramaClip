# 02 · 总体架构与文档地图

> 本文只描述**跨端共识**：定位、进程结构、职责边界、文档索引。
> 前端（Electron 应用）与服务端（Python）的详细设计分别在 `desktop/`、`service/` 子目录，互不混排。

## 1. 项目定位

**DramaClip 是一款本地优先（local-first）的短剧自动高光剪辑工具，面向短剧推广达人（短剧 CPS 从业者）。核心能力：导入短剧视频 → AI 智能分析 → 自动生成多种风格的推广短视频。**

| 维度 | 本地优先的要求 |
|------|---------------|
| 媒体处理 | ASR、场景切割、音频分析、剪辑、编码、字幕、消重 —— 100% 本地执行 |
| 数据 | 全部落本地（SQLite + 文件目录），无云端账号，不上传素材 |
| LLM | 唯一外部依赖：OpenAI 兼容抽象，云端默认、本地端点可切，切换后完全离线（ADR-005） |

## 2. 进程结构

```
┌───────────────────────────────────────────────────────────────┐
│ Electron 应用（desktop/，"前端"）                               │
│  React 渲染层 ──preload typed API──▶ 主进程（薄壳）              │
│                                     ├─ 窗口/对话框/文件系统      │
│                                     ├─ pipe-server（套接字服务端）│
│                                     └─ ServiceManager（进程管理）│
└──────────────────────────┬────────────────────────────────────┘
                命名管道/UDS │ NDJSON + token（03-IPC协议规范）
┌──────────────────────────▼────────────────────────────────────┐
│ Python 服务（service/，"服务端"）                               │
│  transport（连接客户端）→ api（方法注册）→ engines（业务引擎）    │
│                                        └→ infra（存储/FFmpeg/  │
│                                           配置/任务/模型管理）    │
└───────────────────────────────────────────────────────────────┘
```

## 3. 职责边界（三条铁律）

1. **渲染层不碰系统**：React 只通过 preload 暴露的 typed API 通信，禁止出现任何 Electron/Node API；
2. **主进程保持薄壳**：只做窗口、对话框、文件系统、套接字服务端、Python 进程管理、事件转发，业务逻辑为零；
3. **Python 服务独占数据与业务**：SQLite、模型、FFmpeg、所有分析/剪辑/编码业务都在服务端（ADR-006）。

服务端内部依赖方向单向：`transport → api → engines → infra`，禁止反向。

## 4. 端到端协作（概览，细节见两侧详细设计）

- **调用链**：渲染层 → preload → 主进程 ipc → pipe-server → Python api → engines → 原路返回；
- **进度回流**：engines → notify → 管道通知 → 主进程转发 → 渲染层 taskQueue；
- **生命周期**：主进程先监听 → spawn Python → hello 握手（token + 版本）→ 心跳保活 → 崩溃按重启策略退避拉起 → 退出时优雅 shutdown。
