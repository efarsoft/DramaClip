# desktop/01 · React 渲染层设计

> 铁律：渲染层不碰系统——一切后端能力经 `services/client.ts` 唯一出口（总体架构第 3 节）。
> RPC 方法与数据结构见全局 `03-IPC协议规范.md` 与 `protocol/`；**视觉规范以 `03-UI设计方案.md` 为准**，本文只管结构、路由、状态与交互逻辑。

## 1. 信息架构与路由

**单层导轨 + 页面内阶段条**（信息架构以 `docs/superpowers/specs/2026-09-10-dramaclip-ui-redesign-design.md` §2 为准，本节只记结构落地）：

- 导轨清单是唯一真相源：`src/app/navItems.ts`（数据）+ `src/components/layout/Rail.tsx`（渲染）。
  加一页 = 在 `navItems.ts` 追加一项 + 在 `src/app/routes.ts` 登记路径，不改 `AppLayout`。
- 分两组，中间一条 `border/subtle` 分隔线：上组 = 生产循环（工作台 / 项目 / 成品），
  下组 = 配置与元信息（引擎 / 设置）。终态 8 项，「队列」属 P-2.5、「工具箱」属 P-3.4、「关于」属 P-3.6。
- 高亮按前缀匹配（`navItems.ts` 的 `isNavActive`）：根路径精确匹配，其余"自身或子路径"命中，
  所以 `/engines/llm` 保持「引擎」高亮、`/projects/:id/analysis` 保持「项目」高亮。

| 路由 | 页面 | 备注 |
|------|------|------|
| `/` | 工作台：今日待办 / 3 统计芯片 / 最近成品 6 条 / 继续上次 ｜ 右栏 环境就绪度 + 快速上手 | 规格 §4.1 |
| `/projects` | 项目管理：卡片网格 + 新建 + 重命名/复制/删除 | P-3.2 改名 `/dramas` 并按 §4.2 重写 |
| `/projects/:id/analysis` | 智能分析工作台 | P-3.2 合并进剧空间 `/drama/:id` |
| `/projects/:id/produce` | 出片中心：选模式 + 一键出片 + 出片记录 | 同上 |
| `/works` | 成品库：跨项目已完成成片 | P-3.3 按 §4.5 改为按剧分组 + 逐片封面 + 自检徽章 |
| `/engines`、`/engines/:tab` | 引擎中心：总览 / ASR / TTS / LLM | 原 `/models`，P-1 已更名 |
| `/settings` | 偏好设置：出片 / 分析 / 下载 / 硬件 | §4.6 的「生产线默认值」「字幕」分区归 P-3.2 |

- HashRouter（兼容 `file://` 加载）；
- 旧路径重定向表驱动：`routes.ts` 的 `LEGACY_REDIRECTS`（静态一跳）与 `LEGACY_PARAM_REDIRECTS`
  （保住路径参数），由 `router.tsx` 的 `LegacyParamRedirect` 消费。**只留一跳，旧组件同期删除**，
  不留暗组件（规格 §2.2）。
- 一致性由 `src/app/__tests__/iaContract.test.ts` 守卫：导轨 ↔ 路由清单 ↔ `router.tsx` 的
  `path`/`to` 字面量三方必须相符，改名漏一处当场红。
- "继续上次"：`src/stores/lastDrama.ts`，localStorage 记忆上次打开的剧（**只记位置**，
  非 v1 断点续剪，ADR-007 语义不变）。

底部状态栏（`components/layout/StatusBar.tsx`）常驻：Python 服务状态圆点、FFmpeg、GPU、应用版本。导轨不含任何状态信息。

## 2. features 组织约定

```
src/features/<domain>/
├── <Domain>Page.tsx        路由入口组件
├── components/             域内组件
└── api.ts                  域内 RPC hooks（useXxx）
```

- 域内自含，**禁止跨 feature import**（05 规约边界规则）；
- 组件被第二个域复用时才上提 `src/components/`；
- 单文件 ≤300 行、单函数 ≤60 行，超限即拆；
- 布局壳（侧边栏/导航/底部状态区）放 `components/layout/`。

## 3. 状态管理（Zustand）

**只放真正的全局状态**，域内状态留在组件/hooks：

| store | 状态 | 更新来源 |
|-------|------|---------|
| `stores/taskQueue` | 任务表 `{jobId, type, status, percent, message, result?}` | Python `progress.update` 事件驱动为主；服务重启后 RPC 批量补查一次 |
| `stores/ui` | `serviceStatus(starting/ready/restarting/unavailable)`、`currentProjectId`、侧边栏折叠、上次编辑位置 | 主进程 `service:event` + localStorage |

## 4. IPC 封装（services/client.ts）

```ts
client.rpc<T>(method, params): Promise<T>   // 类型由调用方从 @dramaclip/protocol 指定
client.onServiceEvent(cb): () => void       // 订阅通知，返回取消函数
client.restartService(): Promise<void>      // 侧边栏重启按钮
client.appVersion(): Promise<string>
```

- 各 feature 的 `api.ts` 基于 client 封装域方法（如 `analysisApi.prescreen(projectId)`）；
- 组件**永远不直接**调 `window.dramaclip`（lint + 评审约束）；
- 错误统一抛 `RpcException{code, message}`，由调用方映射为 antd message/notification（-32x00 分段 → 中文文案）。

## 6. 页面设计要点（交互逻辑；视觉见 03-UI设计方案 §7）

- **工作台**：统计卡可点击跳转；系统状态行内联"重启/处理"操作；W1 仅渲染服务状态卡（app/service/协议版本，真实 RPC 往返）。
- **智能分析**：≤15 集直接全量并展示逐集进度；>15 集后台预筛 → **3 秒倒计时自动开始推荐集（可取消）** → 同屏展示未推荐集勾选加入；无 LLM Key 显示降级提示。
- **模式配置**：分析未完成时门禁提示；推广策略在此唯一配置；多选模式 + 配置面板（标签切换或统一设置）；底部"仅生成选中 / 一键全部生成"。
- **生成进度**：三共享节点（无 TTS 模式 TTS 节点显示"跳过"）；各模式独立进度与失败重试；完成态跳导出或进时间线。
- **时间线**：W4 只读（预览播放 + 四轨渲染 + 指针联动 + 缩放）；P2 再开编辑（详见 03-UI §7.6 分级说明）。
- **导出管理**：任务表格即导出历史（v1 的"导出历史"功能并入此处，不再单列）。
- **模型管理**：下载进度走 `models.download_progress` 事件；本地导入拖拽区。
- **系统设置**：四区块 + 分区块恢复默认；性能区 LLM 为**端点三元组配置**（预设 DashScope/Ollama/自定义 + 测试连接），非"本地/云端"二选一（ADR-005）。

## 7. 主题与视觉落地

- 视觉权威 = `03-UI设计方案.md`；实现方式 = antd 5 `ConfigProvider` token 映射（色板/圆角/间距 → `styles/theme.ts`），**不手写 antd 已有控件**；
- 自研组件清单：侧边栏（含折叠与项目导航组）、时间线画布、统计卡、进度条微光动画；
- 深色标题栏由主进程 `nativeTheme.themeSource='dark'` 保证（见 desktop/00）。

## 8. 错误与空态

| 场景 | 处理 |
|------|------|
| 服务不可用（unavailable） | 全局顶部警示条 + 页面降级为只读提示（03-UI 未覆盖，此处补定） |
| RPC 失败 | antd message 错误码 + 文案映射 |
| 空态 | 统一 EmptyState（插画 + 引导 + 主按钮） |
| 长任务失败 | taskQueue 标记 failed + 保留 error，支持一键重试（重新提交 job） |
