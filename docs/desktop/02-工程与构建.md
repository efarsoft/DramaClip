# desktop/02 · 工程与构建

> 对应代码位置 `desktop/`。质量工具规则见全局 `04-代码质量规约.md`。

## 1. 构建拓扑

Vite 单工程三产物（vite-plugin-electron 编排）：

| 入口 | 产物 | 说明 |
|------|------|------|
| `src/main.tsx`（index.html） | `dist/` | 渲染层（React，HMR） |
| `main/index.ts` | `dist-electron/main/` | 主进程（CJS，外部化 electron） |
| `main/preload.ts` | `dist-electron/preload/` | 预加载脚本（CJS） |

- 路径别名 `@ → desktop/src`；
- dev server **固定端口 5180 + strictPort**（消灭 v1 动态嗅探端口的脆弱性）；
- `package.json.main = dist-electron/main/index.js`。

## 2. 开发流程

```
npm run dev（根目录）
  → scripts/dev.mjs
      cd desktop && 设置 VITE_DEV_SERVER_URL=http://localhost:5180
      → vite 启动（react HMR + electron 插件构建 main/preload 并自动拉起 Electron）
          → main/index.ts 读 VITE_DEV_SERVER_URL 加载页面
```

热更新边界：渲染层改动即时 HMR；**主进程（main/）改动需重启 Electron**（vite 插件会自动 rebuild，但不会自动重启进程——P2 评估自动重启）；Python 服务由 ServiceManager 管理，进程退出即自动重启。

## 3. TypeScript 策略

| 配置 | 覆盖 | 要点 |
|------|------|------|
| `tsconfig.app.json` | `src/` | strict + noUncheckedIndexedAccess；DOM lib |
| `tsconfig.node.json` | `main/` + 配置文件 | node types；同样 strict |
| `tsconfig.json` | — | 仅引用上面两份（solution style） |

- preload 的 API 类型通过 `import type { DramaClipApi } from '...preload'` 进入渲染层（类型穿越，无运行时依赖）；
- 跨端业务类型一律来自 `@dramaclip/protocol`（workspace 依赖，直接消费 TS 源码）。

## 4. 测试

- vitest；默认 jsdom 环境，协议/网络类测试文件头部标注 `// @vitest-environment node`；
- 测试与源码同目录（`__tests__/` 或 `*.test.ts(x)`）；
- 契约同步测试落在本包：schemas `x-methods` ↔ `METHOD_NAMES` 集合相等。

## 5. 依赖清单（W1 基线，准入制）

| 依赖 | 理由 |
|------|------|
| react / react-dom / react-router-dom / antd / dayjs(antd peer) / zustand | UI 基线 |
| electron 33 / vite 6 / @vitejs/plugin-react / vite-plugin-electron | 构建基线 |
| typescript / eslint 系 / vitest / jsdom / @testing-library/react | 质量门禁 |

新增依赖必须登记理由（04 规约第 4 节）。recharts（情绪曲线 W3 时再引入）、electron-builder（P2）暂不进包。

## 6. 打包（P2，占位）

- PyInstaller 产出 `dramaclip-service.exe` → sidecar（`scripts/build-service.py`）；
- electron-builder：NSIS + zip 双目标，内嵌 `resources/`（ffmpeg/字体/预设/sidecar），模型不入包按需下载；
- 自动更新：P2 评估 electron-updater。
