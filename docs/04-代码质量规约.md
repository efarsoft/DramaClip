# 04 · 代码质量规约

> 核心原则：**宁可少而正确**。任何门禁不满足时先修再提交，不留"以后再说"。
> CI 三道门：lint / typecheck+mypy / test —— 任一红灯禁止合入。

## 1. TypeScript（desktop / protocol）

### 语言与类型

- `strict: true` 全开，另加 `noUncheckedIndexedAccess`、`noImplicitOverride`、`verbatimModuleSyntax`；
- **禁止 `any`**（显式与隐式）；未知数据用 `unknown` + 类型收窄；
- 类型断言 `as` 必须伴随理由注释；
- 跨端业务类型一律从 `@dramaclip/protocol` 导入，禁止在业务代码重定义（v1 教训：双份类型已漂移）。

### 体量红线（ESLint 强制）

- 单文件 ≤ 300 行（`max-lines`，跳过空行注释）；
- 单函数 ≤ 60 行（`max-lines-per-function`）；
- 超限必须拆分，不允许 eslint-disable 绕过（disable 需在 PR 说明理由）。

### 边界规则

| 规则 | 强制方式（W1） |
|------|---------------|
| renderer（src/）禁止 import electron / node:* | ESLint no-restricted-imports |
| components/ 禁止 import features/ | ESLint no-restricted-imports |
| features/* 之间禁止横向 import | W1 人工评审；后续引入 eslint-plugin-boundaries 硬化（依赖准入） |
| 渲染层仅经 src/services/client.ts 访问 IPC | 人工评审 + preload 唯一桥 |

### 命名

- 文件 kebab-case；React 组件文件 PascalCase；类型 PascalCase；布尔值 is/has/can 前缀。

## 2. Python（service）

### 工具链

- **ruff**：lint + format，规则 `E/F/W/I/UP/B/SIM`，行宽 100；
- **mypy strict**：类型注解 100%。
  > 「公共函数/类必须有 docstring」这条已于 2026-09-10 删除：实测 137 处公共函数无 docstring，既无工具校验（ruff 未启用 `D` 规则）也无评审执行过，留着只会让每次审查重新解释"为什么这次要遵守"。**非显而易见的约束仍应写在注释里**（现有实践不变），只是不再当作全员义务。

### 分层（依赖方向单向，禁止反向 import）

```
transport → api → engines → infra
```

- `engines/` 不得 import `transport` / `api`；
- `infra/` 不得 import `engines` / `api`；
- 分层违规在 code review 拦截（后续可加 import-linter 工具化）。

### 数据建模

- 跨进程边界的数据结构一律 **Pydantic v2** 模型，字段与 `protocol/schemas` 对齐；
- SQLite 访问一律经 `infra/storage/repos/`，禁止 engines 内裸写 SQL。

### mypy strict 与无类型第三方库的预案

librosa / opencv / scenedetect 等库缺类型标注，引入时在 `pyproject.toml` 按模块登记
`[[tool.mypy.overrides]] ignore_missing_imports`，**禁止全局关闭 strict**（v1 教训：为过 CI 整体放宽后类型检查名存实亡）。

### 命名

- 模块/函数 snake_case；类 PascalCase；常量 UPPER_SNAKE。

## 3. 契约同步（protocol/）

- 所有跨端数据结构与 RPC 方法在 `protocol/schemas/` **只定义一次**；
- TS 侧 `METHOD_NAMES` 常量、Python 侧 `Router.method_names` 与 schema `x-methods` 三方一致：
  - Python 测试：加载 schemas 汇总方法名 ↔ Router 注册表，集合相等；
  - TS 测试：加载 schemas 汇总方法名 ↔ METHOD_NAMES，集合相等；
- 中期目标：quicktype 类 codegen 直接从 schema 生成两侧类型，消灭手写对齐。

## 4. 工程纪律

- **提交**：Conventional Commits（feat/fix/docs/refactor/test/chore），每个提交可独立构建；
- **测试与实现同批落地**：不写"以后补测试"；引擎类模块（消重/预筛打分/ASS 生成/对白筛选/混音）单测覆盖率 ≥ 80%；
- **依赖准入**：新增第三方依赖必须在提交说明给出理由；stdlib 或既有依赖可解决的不引入；
- **纯逻辑优先抽离**：进程/IO 粘合代码（service-manager、pipe-server 等）中的决策逻辑抽成纯模块单测（restart-policy、ndjson 即此模式）。

## 5. 明确禁止（v1 教训制度化）

1. `.gitignore` 裸通配（v1 的 `_*.py` 静默吞掉 `__init__.py`，导致后端在干净机器上 import 崩溃）；临时文件模式必须带路径前缀；
2. 同一概念双处定义（类型、通道名、常量）；
3. 死代码与注释掉的代码入库（要删就删，git 有历史）；
4. 超长文件继续堆叠新功能（v1 HomePage.tsx > 500 行）；
5. 为过门禁而放宽门禁。
