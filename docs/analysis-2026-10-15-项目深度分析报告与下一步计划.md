## 一、项目现状总览

### 1.1 产品定义与技术栈
**DramaClip** = 本地优先（local-first）的短剧推广短视频全自动剪辑桌面工具。导入一部 80 集短剧 → AI 分析 → 自动生成多种风格、可直接发布的竖屏推广短视频（9:16 1080×1920，EBU R128）。目标用户是短剧 CPS 推广达人（个人/小工作室，抖音/视频号/快手矩阵）。

- **前端**：Electron 44 + React 19 + TS strict + AntD 6 + Zustand 5 + Vite 8（生产代码 ~20,450 行 / 测试 ~9,499 行，11 个 feature 域）。
- **服务端**：Python 3.12 sidecar（PyInstaller onedir ~1.1GB），JSON-RPC 2.0 over 127.0.0.1 环回 TCP + NDJSON + token；SQLite WAL 单一写入者；FFmpeg 8.1.1 随包（resources/ffmpeg，入库 193MB）。
- **模型栈**：paraformer / RapidOCR(PP-OCRv6) / Qwen3-VL / Kokoro / edge-tts / IndexTTS-2.5 / CosyVoice / MDX-Net。
- **工作流四阶段**：进素材 → 分析（ASR×OCR 融合 / 场景切割 / 视觉轨 / 说话人分离）→ 规划（LLM 跨集编排，十种出片模式）→ 出片（段级切割 / 字幕烧录 / 混音 / EBU R128）。
- **契约规模**：81 方法 / 14 命名空间，TS 与方法名集合相等测试通过。

## 二、七维度发现汇总

### 2.1 产品维度（许可研）
- **真护城河候选**：整剧跨集编排 + 短剧垂直融合管线（OCR×ASR 拿片方校对硬字幕当金标准），不在模式数量。
- **最大单点风险**：BUS factor=1（唯一开发+决策+客服），业主的领域 know-how 既是护城河也是风险。
- **功能成熟度**：四阶段核心能力"真可用"，但 LLM 硬依赖七处（七个解说模式文案/真名推断/金句/标题/跨集编排）对新用户是硬门槛；第十模式 highlight_cut 无真机回归。
- **指标纪律优秀**：拒绝虚荣指标（点赞/播放是用户运营指标非工具指标），北极星建议=周活跃出片项目数；复跑率可测通道缺失。
- **商业化**：建议"先买断（A）后增值（C）"，前置三缺位（检查更新/规模度量/付费意向验证）。

### 2.2 架构维度（梁承宇）

## 三、分歧裁决（以当前 HEAD `3fedb9a` 实测为准）

### 裁决 2 · 三处并发缺陷是否真实存在
- 程不宕（10-10 快照）称 pause_split.py 不存在、全仓 24 处 subprocess 均带 timeout → 该缺陷不可复现。

- **结论**：**三处并发缺陷（pause_split 无 timeout / vision close 无 wait / cosyvoice 未接线）全部按当前 HEAD 实测成立**。程的"ffmpeg 无 timeout 不可复现"基于过时快照，已被推翻。

### 裁决 3 · 云端凭据镜像范围
- 程不宕（10-10 快照）称仅 `_mirror_llm_settings` 镜像 llm.* 三键、无 `_MIRROR`、asr/tts 走 settings 直通。

### 裁决 4 · "连播 25 条/轮"上限（幽灵约束 + 简报误归属）
- **溯源结论（三方一致）**：颜可心（前端）、程不宕（后端）grep 两端零命中；许可研反查全仓"连播"全文零命中；所有"25"字样均为 raw_clip 的 3–25s 窗口时长参数。**该上限当前代码里根本不存在**，既非 UI 限制也非队列限制。
- **归因修正**：此条在任务简报中被标注为"产品侧发现（许可研）"，但许可研复核其 task #1 交付全文（§6/§7/§8）未含"连播"一词——**源头停在简报本身，是对许可研的误归属**，非代码/文档实体，亦非其产出。
- **产品侧裁决**：不按 bug 也不按新需求实现（违反 copyTruth「没实现的能力不许写」纪律）；三方一致"代码不动、`export.submit` 维持 `minItems:1`，无阻塞"。
- **待业主定性**：极可能源自业主口述的"平台单账号连发限制"被记成代码约束。若确为业主真实意图（平台连发约束），应归**发布/分发域**——DramaClip 本地优先、不替用户发布，硬 count cap 不符架构，最多做"单账号连发条数建议"软提示，不应塞进后端 `export.submit`。**此条非技术债，不阻塞交付，仅剩"若立约束需业主口径"一个开放项。**

## 六、商业化与成功指标建议（许可研方案）

### 6.1 成功指标（拒绝虚荣指标）
- **北极星**：周活跃出片项目数（每周至少产出 1 条成片的活跃项目/用户）。
- 成片一次通过率 ≥70%；人工干预 ≤1 次/条；LLM 失败率 <10% 且失败带原因可见；首启完成率 ≥60%。
- **明确排除**：成片平台点赞/播放/转发（是用户运营指标非工具指标）；LLM 六维均分（只能排序不能 KPI）；GitHub star/公众号涨粉。
- **复跑率（周）可测通道缺失**：本地优先与数据采集有张力，建议仅做 **opt-in 匿名事件遥测（只报事件不报内容）**，否则留存永远盲猜。

### 6.2 商业化路径
- **选项 A 买断（¥199–399）**：与本地工具心智匹配、零服务器成本，适配度最高。
- **选项 B 订阅（¥29–69/月）**：项目制生意下用户为无剧月份付费意愿低，适配度中。
- **选项 C 买断+增值（基础买断含本地全功能；增值：云端 LLM/TTS 额度/选题库/优先支持）**：作为第二阶段。
- **取舍**：先 A 后 C。商业化三前置缺位（检查更新+激活机制、规模/留存度量通道、定价前付费意向验证）不解决，任何定价都是拍脑袋。
