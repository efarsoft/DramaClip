# 算力与驱动统一方案（唯一权威口径）

> 本文件是项目全部「什么硬件 → 走什么线路」问题的唯一答案页：加速通道、驱动要求、
> 下载线路、用户可见话术都在这里对表。散在各规格里的结论与本文冲突时，以本文为准；
> 本文改动须经业主裁决并同步对应实现。

---

## 0. 四条公理（全部线路的设计根基）

1. **安装态 ≠ 运行态，一切以回执为准。** 装了 CUDA 运行库不等于用了 GPU；每次真实
   运行落 `compute` 回执（请求/解析/实际/回退/原因），UI 只读回执，不从安装态猜。
2. **`auto` 才允许回退并记账，显式请求是承诺。** 显式 `cuda` 失败即报错，绝不静默换
   CPU/DML；`auto` 允许试 GPU 后落 CPU，但原因必须可见。
3. **每条线路都有降级链，降级必须可见且产物可用。** 没有任何一条线是单点。
4. **云端是线路之一，不是异类。** 本地通道不就绪时云端是正解，按量计费进引导话术。

## 1. 硬件分档 → 线路总矩阵

| 机型档 | 转写 ASR | 音色克隆 TTS | 人声分离 | 视频编码 | 引导策略 |
|---|---|---|---|---|---|
| **N 卡·新**（sm≥7.0，RTX20/30/40/50、GTX16） | funasr/whisper 走 CUDA | CUDA | CUDA EP | NVENC | 本地全绿，零打扰 |
| **N 卡·存量**（sm 5.2~6.9，GTX10、M4000、GTX9xx） | funasr 走 CPU；whisper 需 sm≥6.1（5.2~6.0 亦 CPU） | CPU（torch 需 sm≥7.0） | CUDA EP（ORT 兼容实测 sm 5.2 可用） | NVENC（老卡可用则用） | **TTS 页出云端引导**（能力感知，5a07763）；ASR/分离照常本地 |
| **AMD 独显** | CPU | CPU | **DML EP**（2.4x 实证） | AMF（真试编） | ASR/TTS 出云端引导；分离本地即快 |
| **Intel Arc 独显** | CPU | CPU | **DML EP** | QSV | 同 AMD 档 |
| **Intel 核显 / 无独显** | CPU | CPU | CPU | QSV（核显机型） | 全负载出云端引导 |
| **云端已启用**（任何机型） | 云端 ASR | 云端合成 | 本地或 CPU | 不变 | 引导消失，回执记 actual=cloud |

XPU / ZLUDA / ROCm / oneAPI **不在矩阵内**——排除理由与重启条件见 §5 与
[xpu-directml 评估规格](superpowers/specs/2026-10-20-xpu-directml-adaptation-eval.md)。

## 2. 驱动统一口径

### 2.1 NVIDIA（唯一有驱动门槛的厂商）

- **门槛线：驱动主版本 ≥ 551**（代码唯一事实源 `device_profile._MIN_DRIVER_MAJOR = 551`；
  本项目 CUDA 12 运行库 = cublas 12.4 / cudnn 8.9 / cudart 12.4 / cufft 11.2）。
- 驱动版本决定可用 CUDA 上限：`gpu.snapshot` 探 `max_cuda_version`；不足时
  `device_profile.driver_guidance` 出下载引导（needed/url/min_driver/reason），前端照实展示。
- **算力分层**（同一块 N 卡，不同负载的门槛不同，这是设计不是混乱）：
  - 分离 ORT CUDA EP：sm 5.2 起（M4000 实测可用）；
  - whisper（ctranslate2）：sm 6.1 起，之下如实 `unsupported`；
  - funasr 打包态 / TTS 三引擎（torch）：sm 7.0 起（2.8 轮无更低内核，实测否决过 cu126 兼容轮）。
- 虚拟显示适配器（GameViewer 类）在探测层剔除，不参与任何判据。

### 2.2 AMD / Intel

- 只要求**近年 DX12 驱动**（DML 与 AMF/QSV 都随系统驱动走）；**不装 ROCm、不装
  oneAPI、不装 torch-directml**（三者的排除证据见评估规格 §1）。
- DML 的兼容线 = Windows 10 1709+ 任意 DX12 显卡驱动；无额外安装步骤。

### 2.3 明确不出现的东西

`torch-directml`（维护模式钉死 torch≤2.3.1）、`intel-extension-for-pytorch`（已并入主线停更）、
oneAPI Base Toolkit（XPU 轮自包含后仅源码编译才需要）、ZLUDA（cuDNN 短板 + 断供个人项目）。

## 3. 计算线路明细（每负载的通道优先级）

| 负载 | 通道优先级 | 承诺语义 | 回执 |
|---|---|---|---|
| 转写 ASR | funasr CUDA → CPU；whisper CT2 CUDA(sm≥6.1) → CPU；云端另列 | `asr.device` auto/cuda/cpu；显式 cuda 失败即报错 | `asr.funasr` / `asr.whisper` / `asr.cloud` |
| 音色克隆 TTS | IndexTTS2/CosyVoice CUDA(sm≥7.0) → CPU；云端另列 | `tts.device` auto/cuda/cpu | `tts.indextts2` / `tts.cosyvoice` |
| 轻量 TTS kokoro | CUDA(sm≥7.0) → CPU | 同上 | `tts.kokoro` |
| 人声分离 | **CUDA EP → DML EP → CPU**（auto 三级）；onnxruntime 包按宿主三选一安装 | `tts.device` 同上；显式 cuda 遇 DML 包如实失败 | `tts.separation`，actual 可为 `cuda/dml/cpu` |
| 视频编码 | NVENC → AMF → QSV 真试编 → libx264（段级失败整片统一重跑） | `export.encoder` auto/固定名；硬编不属于 CUDA 承诺 | `video.encode`，actual 为编码器名 |
| AI 生成标注 | 随段编码滤镜烧制（字体缺失/drawtext 失败 = 导出失败） | 跟随编码线路，无独立设备请求 | 并入 `video.encode` |
| 云端 ASR/TTS | 百炼适配器；引擎接线即可用，真可用运行期判 | key 在本地脱敏存储 | `*.cloud`，actual=cloud |

## 4. 下载线路明细（主源 → 降级链 → 失败话术）

| 资源 | 线路顺序 | 备注 |
|---|---|---|
| 模型文件（HF 系仓库） | hf-mirror → huggingface（所选源优先插队） | 提交号布局 + SHA256/blob 对账；「恰好写满」半成品直接对账不触发 416 |
| 模型文件（国内双挂仓库） | **ModelScope 优先** → hf-mirror → huggingface | 五个 iic 仓库的 HF 源有访问门槛（401），auto 永远先走 ModelScope |
| CUDA 运行库 wheel | 清华 → 阿里云 → pypi.org（`/packages/` 路径同构换前缀） | 锚点 SHA256 不随镜像变；三源国内真探全通 |
| onnxruntime（cuda/dml/cpu 轮） | 清华 simple → pypi | 变体按宿主厂商三选一，换变体=重装 |
| UVR 分离模型 | gh-proxy → github 直连 | 单文件 ~50MB |
| torch 轮（运行环境） | 官方 cu 源 → 国内镜像 fallback（GPU 轮）；CPU 轮走 pip 镜像 | 变体：cuda(sm≥7.0) / cpu；xpu 轮存在但不装（§5） |
| 失败分类 | 401 门槛 / 404 迁移 / 5xx 重试 / 磁盘 / 断网，逐条给动作 | 见 `classify_failure` |

## 6. 用户可见口径（UI 话术统一规则）

- 引擎页徽标/引导卡只由 `cloudRecommendation` 一处产生：本地「真能跑的 GPU 通道」
  （caps ready）不存在 + 云端未启用 → 出卡；有卡但卡带不动（能力感知）→ 照出；
  本地就绪或已在云端 → 零打扰。
- 回执话术固定词汇：`本次实际：GPU（cuda:0）/ GPU（DirectML）/ CPU / 云端`；
  `已回退 CPU：<原因>`；`编码：<编码器名>`；unknown 不点绿不编造。
- 驱动不足 → 驱动引导卡（下载链接 + 最低版本），不说「不支持」说「升级驱动后可用」。
- 计费话术只写口径（ASR 按音频时长、TTS 按字符），不编具体价格，标注「以官方账单为准」。
