# DramaClip v2 重构实施方案

## 0. 项目定位（一切决策的锚点）

**本地优先（local-first）的短剧自动高光剪辑工具，面向短剧推广达人（短剧 CPS 从业者）。核心能力：导入短剧视频 → AI 智能分析 → 自动生成多种风格的推广短视频。**

本地优先的架构含义：所有媒体处理（ASR/场景/音频/剪辑/编码/字幕/消重）100% 本地执行；数据全落本地（SQLite + 文件）；LLM 是唯一外部依赖——统一走 **OpenAI 兼容抽象层**，默认云端端点（DashScope 等），设置可切换本地端点（Ollama/LM Studio）实现全离线，P2 评估内置本地模型。

**数据归属总原则**：随应用分发、跟版本走的只读内容（ffmpeg/字体/内置字幕预设）→ `resources/` 文件；用户运行时产生的可变数据（项目/分析结果/导出记录/自定义预设/设置）→ SQLite。

## 2. 核心架构决策（写入 docs/00）

| # | 决策 | 要点 |
|---|------|------|
| ADR-001 | 保留 Electron 33 + React 19，不迁 Tauri | 体积/内存大头是 Python 与模型；宿主层是 I/O 编排；避免三语言栈 |
| ADR-002 | Named Pipe + JSON-RPC 2.0 | Windows 原生管道；单连接双向（请求+进度通知）；非 Windows 退回 Unix socket |
| ADR-003 | 代码 100% 全新重写 | v1 只读参考（backup/）；调优参数提炼为 docs/03 规格输入 |
| ADR-004 | 扁平 monorepo | 根目录平铺 desktop/service/protocol；`service/dramaclip/` 内层=Python 包根（等价 desktop/src） |
| ADR-005 | LLM：OpenAI 兼容抽象，云端默认+本地端点可切 | 见第 0 节 |
| ADR-006 | SQLite 由 Python 服务独占 | 单一写入者；前端/主进程一律经 RPC |
| ADR-007 | 功能集按技术方案完整重规划 | v1 独有功能不默认继承；"AI 标题/简介""导出历史"列 P2 backlog |
| ADR-008 | 字幕预设两层设计 | 内置预设=resources/ 只读 JSON（随版本走，code review 变更）；用户自定义预设=SQLite `subtitle_presets` 表（base_preset_id 派生）；解析顺序：用户>内置>全局默认 |

## 4. 关键流转（对应目录）

- 渲染层调用：`features/*/api.ts` → `src/services/client.ts` → preload → `main/ipc.ts` → ServiceManager → 管道 → `service/dramaclip/api/routes.py` → engines
- 进度回流：engines → `transport/notify.py` → 管道通知 → ServiceManager → ipc → `stores/taskQueue`
- 依赖方向（Python）：`api → engines → infra`，`transport` 只认 `api`，禁止反向 import

## 5. 质量门禁（docs/02，CI 强制）

TS：strict+noUncheckedIndexedAccess、禁 any、strictTypeChecked、features 禁横向 import、单文件≤300 行/单函数≤60 行。Python：ruff(E/F/W/I/UP/B/SIM)+mypy strict、注解 100%、边界数据 Pydantic v2、单向分层。契约：schema 唯一定义，CI 校验两侧同步。纪律：Conventional Commits、测试与实现同批（引擎覆盖率≥80%）、依赖准入制。禁止（v1 教训）：gitignore 裸通配、双处定义、死代码、超长文件。
