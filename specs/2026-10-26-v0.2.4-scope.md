# v0.2.4 范围规划（2026-10-26 业主定调）

**主线：视觉理解 VL 充分使用——声画对位。** 业主判定 VL 当前只落在分析头部、下游消费为空。

## 主线：声画对位（VL 下游消费）

按价值序：

1. **逐段画面窗注入文案生成**（核心）：分析产出的 visual_track 帧描述按时间窗切片，随逐段文案生成注入——文案与"画面里正在发生的事"硬性咬合（声画对位），不再纯靠台词转写推断。接入点：编剧/填词的画面上下文注入面（编剧画面轨的细粒度化）。
2. **开场钩子画面选择**：开场 3 秒质检扩展——VL 反差评分驱动首段画面选择，文案钩子与画面钩子对齐。
3. **封面候选**：分析时顺带产出张力帧候选做封面（帧已过模型，边际成本近零）。
4. **标题视觉维度**：标题生成注入画面级反差。
5. **BGM 情绪校准**（可选）：画面情绪校准选曲。

前置：VL 加速落地——llama.cpp CUDA 构建资产入库（N 卡机）/ Vulkan 轮评估（AMD/Intel，与 audio.cpp v0.3 后端同源思路）；分级使用策略（重头剧/预筛推荐集才开全量 VL）。

**运行时随包（业主 2026-10-26 提议，本机已预置验证）**：llama.cpp Vulkan 构建常态化随安装包分发（类比 FFmpeg 随包内置）——选型锁定 b11889（37MB Vulkan 包，Qwen3-VL 多模态支持，自包含无 CUDA 依赖；N 卡机可另配 CUDA 12.4 包 279MB+cudart），CI 发版步下载解包进 `resources/`；新打包形态的 llama-server.exe 为 9KB 启动器 + llama-server-impl.dll，运行时探测/门禁不变。本开发机已预置解压并通过 `--version` 冒烟（0.6.0-dev build 11518）。

## 追加（2026-10-26 晚，业主裁决）：交叉链实测驱动重排 + 音画同步

**背景**：本机测试两单渲染失败——布局用估算时长排窗口，TTS 实测更长（旁白段越集尾 7.99s；桥段 3.87s 塞不进 2.93s 空隙），`_assert_within_source` 按旧裁决判死。业主裁决：**素材不 fit 应重新选取判断，而不是失败**。

**设计（两道消化层 + 最终防线）**：

1. **顺序倒置（根治）**：合成与布局解耦——先 TTS 实测全部旁白时长，再按实测重排窗口。估算时长退回编剧端做字数预算，布局不再消费。
2. **结构层音画同步**：重排按序保序填隙——原声段窗口钉死（原声对白不可动），旁白/桥段按序填入锚点间空隙；实测 > 空隙 → 依次尝试后续更大空隙 → 全无则定向收短两轮 → 弃段留痕；段起点吸附回 ±0.5s 内最近视觉切点（见 10-27 追记）。
3. **语义层声画对位**：VL 帧描述按取材区间切片注入逐段填词（见 10-27 追记）。
4. **`_assert_within_source` 收窄为最终防线**：重排后不变量仍破坏（代码 bug）才判失败；常规不 fit 一律重排消化。

**2026-10-27 追记：业主拍板 2/3 两项提前进当前版本（原 0.2.4 主线），当日落地**——①切点吸附渲染侧：`synthesize_narration_texts` 新收 `scene_cuts`，实测重排后段起点吸附回 ±0.5s 内最近视觉切点（`_snap_start`，吸附会破坏空隙约束即回退原值；cross 空隙落位/头部扩展/尾部收口三处全覆盖）；②逐段画面实据：`EpisodeMaterial.frames`（装配自 analysis.visual_track，复用 `_visual_frames_of`）+ `frames_in` 区间切片 + 槽位块注入（区间内帧逐条给出/区间外不串槽/无画面轨分档不报错），帧行格式与剧本链共用 `format_frame_line` 单源。收短重写 prompt 暂不带帧（契约=不得新增剧情，原文案已画面一致），留 0.2.4 视实测决定。
