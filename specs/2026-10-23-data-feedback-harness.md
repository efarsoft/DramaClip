# 数据反馈 Harness 规划（0.2.4 · 第二层：数据驱动的选择）

**日期**：2026-10-23 · **状态**：规划（未实施）· **前置**：W8 发布数据回流已落地（026_publish_data）
**上位决策**（2026-10-23 业主问答）：自进化分三层——①人看数据改规则（现在）②数据驱动的自动选择（本规划）③LLM 自动改 prompt（**明确不做**：AI 输出即成品的定位下，自动迭代改坏则每条都坏）。

## 0. 这是什么、不是什么

harness = 把发布数据「跑」成决策输入的固定流程：聚合 → 归因 → 人工确认 → 调权重。
**不是**机器学习，**不是**自动改提示词——每一次权重调整都有人确认，系统只负责把统计事实摆出来。

## 1. 数据模型：回溯路径已就位（W8 落地时备好）

```
publish_data（export_jobs 列，观众投票）
  └─ export_jobs.narration_plan_id（真外键）
       └─ narration_plans.plan_data
            ├─ mode            模式（cross/full/ultra…）
            ├─ angle           卖点角度名
            ├─ arc             叙事母题（十二卡）
            ├─ hook            钩子原句 → 句式分类器（见 §3）
            └─ narration_texts 逐槽文案
```

方案已删的成片（LEFT JOIN 断链）仍计入总量，但归因维度标「不可考」——片子在、
投票真，只是不知道它用了哪套骨架。

## 2. 指标口径

- **主指标**：完播率 `retention_pct`（0-100，创作者后台展示口径）。
- **辅指标**：点赞率 `likes/plays`（可选字段，缺失的条目在该指标里剔除，不补 0）。
- **聚合**：中位数（播放量方差巨大，均值被单条爆款绑架）；同时报样本数。
- **可疑数据纪律**：同一成片重复录入以后录为准（set_publish_data 覆盖写，已是现状）；
  播放量为 0 的条目（删视频/隐私）从分母剔除。

## 3. 统计维度（按归因价值排序）

| 维度 | 来源 | 价值假设 |
|---|---|---|
| 钩子句式 | hook 原句 → 句式分类器 | 开场 3 秒决定划走，句式是与完播最直接的因果候选 |
| 叙事母题 arc | plan_data.arc | 十二卡的轮换本为对抗疲劳，数据来验证哪张卡真的留人 |
| 模式 mode | narration_mode | 解说 vs 纯剪辑的产品级取舍 |
| 角度 angle | plans.angle | 同剧多角度的内容方向验证 |
| 平台 | publish_data.platform | 分发侧差异（同片多平台发的对比最有信息量） |

**句式分类器**（唯一需要新建的部件）：hook 原句 → 六句式（冲突一句话/悬念反问/
金句宣言/行为指令/人物关系三段式/极简剧名式）。口径用 titles prompt 里已有的
六类定义（同一真相源），离线 LLM 单次分类+落库（或规则粗分），批量跑一次即可。

## 4. 信号纪律（防过拟合噪声）

- 每类样本 **<10**：只看趋势，报告灰显，禁入调权依据；
- **10-30**：趋势参考，报告黄标；
- **≥30**：可作为调权依据。
- 单条爆款（完播率离群 >2σ）在报告里单独点名，不进中位数——算法推荐流量下
  一条 500% 完播的 outlier 会把结论带沟里。

## 5. harness 形态：只读报告，不自动调权

**`export.publish_report`（RPC，只读）**：按选定维度聚合，返回
`[{维度值, 样本数, 中位完播, 点赞率, 备注(灰/黄/离群点名)}]`；
界面放成片列表侧栏或工具页，产出一眼可读的表。

**闭环的最后一公里是人工**：报告 → 业主看 → 说「triumph 高、default 低」→
调 `variant_scoring` 六维权重或 `angles` 的选题偏好（改代码常量，走正常提交流程）。
权重的「建议值」可以由 harness 顺手算，但**应用永远是人拍板**——这是与第三层的
分界线，也是「AI 输出即成品」定位下的安全边界。

## 6. 实施切片建议（0.2.4）

1. **报告 RPC + 界面表**（一天）：维度聚合 + 阈值灰黄标。数据从这天起开始「可读」。
2. **句式分类器**（半天）：hook → 六句式落库（回填历史方案）。
3. **权重调整工作流**（半天）：报告页附「建议调整」→ 业主确认 → 生成常量改动 diff。
   这一步做完，第二层闭环完整。

## 7. 明确不做

自动 prompt 改写（第三层）/ 发布数据 API 抓取（平台无公开接口，爬取有合规风险，
W8 已裁决手录）/ 样本不足时的任何自动调权 / 逐段级归因（完播率只到「条」，不到
「段」——手录数据粒度决定的硬边界）。
