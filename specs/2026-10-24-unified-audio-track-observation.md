# 观察记录：解说+音效+BGM 一条音轨直接生成（后续迭代方向）

日期：2026-10-24
性质：业主钦定观察项（非当期任务，不占 W 系列排期）

## 形态

由全模态模型在**同一条音轨**中直接生成「解说语音 + 环境音效 + BGM 音乐」，自然语言指令控制音色、语速、音效类别、音乐情绪。拼接、对齐、混音由模型内部完成，而非外部多轨工程。

存在性证明：Ming-flash-omni-2.0（蚂蚁，2026-02 开源，MIT，100B 总参/6B 激活，Ling-2.0 MoE）——业界首个全场景音频统一生成模型。Ming-3.0 音频家族（2026-10-21/22 发布：asr-tiny / tts-tiny / audio-flash）尚未延续该能力（audio-flash 只做音频理解+语音输出，明确不含 BGM/音乐生成），但同一团队同一技术线，该形态是明确的演进方向。

## 对 DramaClip 的意义

现行成片音频 = 三路外部拼接：

1. 解说 TTS 逐槽位合成（本地 kokoro / 云端 CosyVoice）；
2. BGM 床混音（W6 已落地：情绪选曲 + stream_loop + afade + amix，空曲库字节级等价跳过）；
3. 转场音效（W6.2 关项，未实施）。

一条音轨形态若成熟，三路变一路：解说情绪与音效时机由模型按剧本内部对齐，混音不再手工调参，成片听感上限显著抬高。W7 BGM 卡点（已降级为听感对比项）在该形态下整体失效——卡点是拼接工程的补偿手段，模型内生成不需要它。

## 前置条件（全部满足才评估立项）

1. **云端 API 可用**：模型 100B/256GB 权重级，本地部署对主流消费级卡用户不可行；Ming-flash-omni-2.0 目前无官方托管 API，持续观察百炼/蚂蚁自有平台上架。
2. **单条成本可接受**：按集生成的音频生成量对标一次完整 TTS+混音链路的成本。
3. **真机 A/B 显著优于三路拼接**：现行链路是基准（W6 BGM 床已真机可听）。
4. **许可与商用**：Ming 系全家族 MIT 已核；云端 API 上架后按服务条款另核。

## 与现役路线的关系

- 不阻塞任何现役功能：BGM 床、解说 TTS、audit 链照常运转，v0.2.3 发布节奏不受影响。
- 若形态成熟落地：W6 曲库+选曲+混音参数退化为兜底路径保留（曲库资产不浪费）；W6.2 转场音效、W7 卡点永久关闭。
- 关联规格正交：audio.cpp v0.3（specs/2026-10-22-audiocpp-full-audio-migration.md）只涉及 ASR/TTS 适配器与本地栈焚烧，不涉及本观察；Ming-3.0 调研结论见会话记忆 dramaclip-ming3-eval。

## 格局扫描（2026-10-24 同日补充，全模态四线摸底）

结论先行：**钦定形态的触发条件①（云端 API 可用）已由 StepAudio 3 Gen 首家满足**；另浮出两块中间积木（BGM 定制生成、foley 音效），可在形态整体成熟前独立落地。

### 四条线盘点

| 线 | 代表（截至 2026-10） | 与钦定形态的关系 |
|---|---|---|
| 全模态旗舰 | Qwen3.5/3.8-Omni（百炼实时 API：语音输出+音色克隆，**无音效/音乐生成**）、MiniCPM-o 4.5（9B 全双工）、Step-Audio-R1.1/R1.5（语音推理开源）、Baichuan-Omni-1.5 | 输出仅语音——不是本形态路线，排除 |
| 一条音轨 | **StepAudio 3 Gen**（阶跃星辰 2026-09 商用 API：人声+音效+环境音+BGM 单轨统一生成，支持"各声音元素出现位置与先后顺序"的自然语言控制，输入含脚本描述；音量/强度控制未提及）、Ming-flash-omni-2.0（开源独苗，100B 本地不可行） | 形态本体 |
| 视频转音效（foley） | MMAudio v2（CVPR25 开源）、ThinkSound（阿里 NeurIPS25 开源，CoT 三阶段）、HunyuanVideo-Foley（腾讯 2025-08 开源）、Kling-Foley（快手）、Foley Control（Stability 轻量适配） | 中间积木＝音效第三路（画面驱动，对短剧动作画面正对口） |
| 音乐生成 | **ACE-Step 1.5**（Apache-2.0，Qwen3-LM 规划+扩散渲染，社区口径 <4GB 显存、生成秒级、最长 10 分钟、人声/纯器乐可选、风格控制/人声转 BGM）、DiffRhythm（中文歌）、YuE2（24GB）、MusicGen（纯器乐短段） | 中间积木＝BGM 按剧本情绪定制生成（静态曲库的上位替代） |

### 触发条件状态更新

1. **云端 API 可用 → 已满足**（StepAudio 3 Gen，StepFun 开放平台；其 TTS 系参考价 2.5 元/万字符，Gen/Music 单价未公开检索到，待核）。
2. 单条成本可接受 → 待核（按单集解说文案量与音轨时长对 Gen 单价估算）。
3. 真机 A/B 显著优于三路拼接 → 未启动。
4. 许可 → API 服务条款待核（Step-Audio 开源系多为宽松许可，Gen 权重是否开放未确认）。

### 新增关键约束（形态落地硬门槛）

- **解说逐字保真**：解说成片文案是逐字稿（audit 链产出的成品），模型即兴改词不可接受。StepAudio 3 Gen 有"脚本描述"输入但文档未承诺逐字保真——接 API 后第一件事是逐字保真测试；**不过关则形态退化为「音效+BGM 两成分生成、人声仍走 TTS」的半形态**（价值仍存：省掉音效素材与混音）。
- 音量/强度控制未提供（仅位置与顺序）——BGM 床的音量校准经验不可迁移，成片响度链（loudnorm 前置于 BGM 床之后）可能仍需外挂兜底。

### 中间积木（形态整体成熟前的可落地位，均待业主点单）

- **BGM 定制生成**：ACE-Step 1.5 本地生成纯器乐 BGM 替换静态曲库（Apache-2.0 商用干净；显存社区口径 <4GB，须真机核）。业主此前"numpy 编曲不可做"的空白由它补上；可做半日 spike：五情绪 prompt → 生成曲 vs 曲库 A/B。
- **音效第三路**：foley 线四家开源，但扩散模型 RTF 与体量未核——立项前提是 RTF 可接受或有云端 API。
