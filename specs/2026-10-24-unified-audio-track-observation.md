# 观察记录：解说+音效+BGM 一条音轨直接生成（后续迭代方向）

日期：2026-10-24
性质：业主钦定观察项（非当期任务，不占 W 系列排期）

## 形态

由全模态模型在**同一条音轨**中直接生成「解说语音 + 环境音效 + BGM 音乐」，自然语言指令控制音色、语速、音效类别、音乐情绪。拼接、对齐、混音由模型内部完成，而非外部多轨工程。

存在性证明：Ming-flash-omni-2.0（蚂蚁，2026-02 开源，MIT，100B 总参/6B 激活，Ling-2.0 MoE）——业界首个全场景音频统一生成模型。Ming-3.0 音频家族（2026-10-21/22 发布：asr-tiny / tts-tiny / audio-flash）尚未延续该能力（audio-flash 只做音频理解+语音输出，明确不含 BGM/音乐生成），但同一团队同一技术线，该形态是明确的演进方向。

## 对 DramaClip 的意义

现行成片音频 = 三路外部拼接：

1. 解说 TTS 逐槽位合成（本地 kokoro / 云端 CosyVoice）；
2. BGM 床混音（W6 已落地：情绪选曲 + stream_loop + afade + amix，空曲库字节级等价跳过）；
3. 转场音效（W6.2 关项，未实施）。

一条音轨形态若成熟，三路变一路：解说情绪与音效时机由模型按剧本内部对齐，混音不再手工调参，成片听感上限显著抬高。W7 BGM 卡点（已降级为听感对比项）在该形态下整体失效——卡点是拼接工程的补偿手段，模型内生成不需要它。

## 前置条件（全部满足才评估立项）

1. **云端 API 可用**：模型 100B/256GB 权重级，本地部署对主流消费级卡用户不可行；Ming-flash-omni-2.0 目前无官方托管 API，持续观察百炼/蚂蚁自有平台上架。
2. **单条成本可接受**：按集生成的音频生成量对标一次完整 TTS+混音链路的成本。
3. **真机 A/B 显著优于三路拼接**：现行链路是基准（W6 BGM 床已真机可听）。
4. **许可与商用**：Ming 系全家族 MIT 已核；云端 API 上架后按服务条款另核。

## 与现役路线的关系

- 不阻塞任何现役功能：BGM 床、解说 TTS、audit 链照常运转，v0.2.3 发布节奏不受影响。
- 若形态成熟落地：W6 曲库+选曲+混音参数退化为兜底路径保留（曲库资产不浪费）；W6.2 转场音效、W7 卡点永久关闭。
- 关联规格正交：audio.cpp v0.3（specs/2026-10-22-audiocpp-full-audio-migration.md）只涉及 ASR/TTS 适配器与本地栈焚烧，不涉及本观察；Ming-3.0 调研结论见会话记忆 dramaclip-ming3-eval。
