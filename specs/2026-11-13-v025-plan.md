# v0.2.5 更新计划（2026-11-13 与业主讨论定稿）

- 前版：v0.2.4（发版待业主人工测试确认，tag 仅业主明确确认后打）
- 本版主题：**让 0.2.4 的两条主线的「最后一公里」落地**——视觉 GPU 开箱即用 + 画面/说话人信息用得准
- 挂账上游：视觉/OCR 提速的实测数据见 2026-11-12 会话（M4000 三后端对测、OCR 线程剖面）

## 主题一：视觉 GPU 开箱即用（主打）

现状：卸载代码已上线（0.2.4），但 llama.cpp CUDA 构建要用户自行获取放置——终端用户实际用不上。

- **1.1 llama.cpp 进资产库**：引擎中心一键下载 CUDA 构建。双源（gh-proxy 直连兜底）+ SHA256 对账 + 解压落位 `data/tools/llama.cpp` + 体检入档；注册表加行模式有先例。约 1~2 天。**依赖：RTX 3060 标准机验证**
- **1.2 OCR 预扫 GPU 化**：rapidocr `use_cuda` + 失败回退 CPU + M4000 真机 A/B（速度与识别质量双对拍）。十集 20 分钟 → 约 4 分钟（首核实测：CPU 地板 ~720ms/帧，线程调优已被否）。半天~1 天
  - **决策点（实施时拍）**：主 venv 直装 onnxruntime-gpu（ml extra 换轮，安装包 +200MB）vs OCR 挪独立 worker venv（零体积，多一跳）——ORT CPU/GPU 两包互斥不能同 venv（DirectML 评估实证）

## 主题二：说话人分离补全

现状：分离链在跑（本剧 28/29 段带标签落库），但界面零渲染、标签是真名靠 LLM 猜、重 BGM 塌缩只发 warning。

- **2.1 转写卡显示说话人**：行前缀 `角色A` 标签或按角色着色——纯前端，数据现成。小
- **2.2 角色真名映射**：转写编辑支持改 speaker / 小映射面板（角色A→汪言），映射结果喂文案链——audit「真名规则」从 LLM 猜变为确定性输入。**设计决策（实施时拍）：映射存放位置**（project.settings vs 独立表）。中
- **2.3 塌缩自动降级**：重 BGM 塌缩检测（pipeline.collapse_warning）命中时丢 speaker 标签回退纯文本，错误标签不再污染文案。小

## 主题三：画面驱动选段（VL 充分利用，业主 2026-11-13 提出）

现状（代码实证）：冲突打分只喂台词（哑段结构性垫底）；`has_dialogue` 把哑段剔出全部原声窗；VL `watch_score` 全链只在开场首帧双因子用过一次——**视觉炸裂的无台词场景在选段池里隐形**。

- **3.1 哑段成为解说画布**：解说模式的旁白槽画面从「落在哪算哪」改为从「哑段 × 高 watch_score × VL 描述」池选；槽位 brief 引用 VL 描述，解说照画面写。**红线不破：10-20 裁决（原声窗哑段孤插）不动——哑段只进有解说压着的覆盖窗，不进原声窗**。中
- **3.2 原声窗画面加成**：窗级综合分加画面项（窗内帧 watch_score 分布），不只开场首帧；**黄金集对拍防排序漂移**。小~中
- **3.3 采样加密：不进本版**——待真实素材漏帧率数据再定（GPU 提速后 24~32 帧或镜头切换点加权采样可行）

## 主题四：门禁与韧性

- **4.1 avsync/ending 升门禁**：红→定位坏段→单段重掷→复测，每片至多 1 次，二次红留痕出片。**数据门槛：自检影子数据当前为空（export_jobs.selfcheck 全空），需业主对成片点「补测此片」出假红率，≈0 才上门禁**；数据不到位则顺延
- **4.2 分析闸位预占**：submit 前 acquire，收掉池饱和两槽全灭。小~中

## 主题五：小批次

- **5.1 提示词注册表单源等价重构**：逐字节等价断言零行为风险。半日
- **5.2 Agent 协作六条**：待业主点单，默认不进本版

## 主题六：成片实测修复（2026-11-13 七部成片体检产出，业主点名列入）

体检口径：两个项目 7 部成片（钟 5 部 + 海狱 2 部）逐部 ffprobe + 响度/静音/黑屏/冻结四检 + 抽帧目检（蒙太奇 + 全分辨率定点帧）。
机械层全绿：响度七片全部 -14.0±0.1 LUFS（目标 -14 ✓）、无 >0.8s 静音、无黑屏、无 ≥2s 冻结、画幅跟首源正确、30fps h264 一致——**音频与编码管线稳，问题集中在画面层**。

- **6.1 字幕擦除可靠性（最高优先）**：实测三处实证——①解说黄字与残留原白字重叠打架（钟 dialogue_narration 112s，不可读级）；②两行原字幕带内完整未擦（277s，band=0.711-0.834 与残留位置吻合）；③擦除行为不一致（raw_clip 多数帧干净，dialogue_narration 多帧残留）。根因初判（实施时定位）：OCR 字幕条漏检（两行字幕只登记 1 行、部分驻留窗漏检）+ 行级 delogo 按驻留窗开合 → 漏检处原字幕裸奔；band 上沿偏窄（112s 残字在带外沿）。修复方向：两行/多行字幕检测召回 + 渲染后抽帧自检残字自动补擦 + 解说字幕压位对齐原带（SubtitleCover 机制在库，查未生效原因）。高
- **6.2 金句流多层字幕排版冲突**：海狱 subtitle_flow 帧内白色原声字幕与红色 CTA/金句卡垂直叠压（抽帧 4 实证）。小~中
- 6.3 记录不立项：文案错字上屏个案（「内丹帽子」疑似转写错字）——属转写精炼/audit 覆盖面，挂账观察
- 6.4 记录不立项：时长口径（dialogue_narration 7 分钟/ultra_short 70 秒）——撞「时长让位质量」裁决，不动
